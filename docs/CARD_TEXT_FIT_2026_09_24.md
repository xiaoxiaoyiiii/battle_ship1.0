## 1. 量出来的两个真缺陷（改之前）

| 卡 | 症状 | 数字 |
| --- | --- | --- |
| 长卡名 | 卡名被名牌裁掉一行 | `scrollHeight − clientHeight = 29px` |
| 长描述 | 说明框溢出（旧写法 `overflow-y:auto` 会出滚动条） | 最长真实描述溢出 **322px** |
| 密集档 46×62 | 名牌 + 类型条总高超过卡高 | 三区总高 **65 > 58** |

两条都不是"看着不对"，是量出来的 —— 与 `UI_DEMO_OPTIONS_2026_09_23.md` §7 的教训同源。

**根因（长卡名）**：名牌是 `display:flex`，卡名作为 flex item 与速阶宝石抢宽度，
被挤到只剩一行的高度。改成「名牌 `display:block` + 宝石绝对定位右上角 + 卡名 `padding-right` 让位」后解决。

## 2. 有意重定的那一条断言（为什么旧口径不再适用）

| | |
| --- | --- |
| **旧口径** | 说明框 `scrollHeight ≤ clientHeight + 1`（一律不许截断） |
| **新口径** | 卡名**不许截断**（真缺陷）；说明框**允许按设计的行截断** —— `-webkit-line-clamp` + `overflow:hidden` + 省略号。<br>"既放不下、又没截断"（`overflow` 可见 → 被卡框切一半）仍判 FAIL。 |

**为什么旧口径不再适用**：卡面是 `86×118`（宽屏档），而最长真实描述 **125 字** ——
量出来要溢出 322px。物理上不可能在一张 86px 宽的卡里放下完整中文描述。
所以按 MTG Arena 的同款做法：**卡内说明框做行截断 + 省略号，完整文本由
二级预览的右侧说明窗（`#magic-card-preview`）与移动端大卡面抽屉承载**。
这是设计选择，不是放宽门禁 —— 门禁仍拦得住"被卡框硬切一半"这种真缺陷。

## 3. 测试输入用真实卡数据（不是编造的）

工具从 `static/magic_card.json` 读全部唯一卡，取：

- **最长卡名的 4 张**（实测最长 = `Freezing！` 9 字符 / `克苏鲁之眼` 5 汉字）
- **描述最长的 4 张**（最长 125 字）

> 为什么不用编造的长名字：卡名长度是**数据事实**。编一个数据里不存在的 7 字名去断言，
> 等于在测一个到不了的状态 —— 与本项目「修 bug 前先实测复现」的原则相悖。
> （上一版工具正是这么写的：用 7 字的「接受神之恩惠吧」断言，结果量出一个真卡永远不会出现的
> 15px 溢出，属于测错了对象。）

## 5. 看图才发现的三个缺陷（**属性断言全都没抓住**）

「验证效果」时按 `tools/acceptance_shots.mjs` 出了两张 native 分辨率的卡面近景
（宽屏 @2x、手机 @3x），一眼就看出三个问题 —— 而当时 §4 那张表**是全绿的**。
教训：`-webkit-line-clamp: 4` + `overflow: hidden` 只是"**声明了**截断"，
**不保证渲染出来是干净的**。这三条现在都有专门的量法（见 §6）。

| # | 症状 | 量出来的数字 | 根因 | 修法 |
| --- | --- | --- | --- | --- |
| 1 | 说明框**拦腰切断半行字** | 盒高 35px、行高 13.392px → 余 8.2px | 盒高由 `flex: 1 1 auto` 撑出来，落在行中间，`line-clamp` 根本没机会生效 | `flex: 0 0 auto` + `max-height: calc(3em*1.35 + 10px)` + `clamp: 3`（三者必须同为 3 行）+ 类型条改 `margin-top:auto` 贴底 |
| 2 | 拉丁卡名被从右边切掉 | `Freezing！` scrollWidth−clientWidth = **20px** | `overflow-wrap` 默认不在词内断行，而 `Freezing！` 是无空格长 token；旧的"不裁字"断言只比**纵向** scrollHeight，横向溢出**量不到** | `.card-name { overflow-wrap: anywhere }` |
| 3 | 大型条「普通魔法」装不下 | 紧凑档溢出 6–8px（speed / type 各一） | 46–64px 宽的卡里塞不下「速阶 N」+「类型魔法」两段文字 | 类型块加 `min-width:0 + text-overflow: ellipsis`（干净收尾）；紧凑/密集/横屏档**隐藏「速阶 N」文字**（速阶已由名牌上的宝石表达） |

> 第 3 条顺带暴露一个反直觉点：**把 `max-height` 与 `line-clamp` 拆开写会互相打架** ——
> 图鉴（9 行）与手机大卡面（8 行）都覆写了 `line-clamp`，但基础规则的 `max-height`
> 是 3 行的，会把它们压回去。三处现在都成对改了，注释里也写明"改一个要同时改另外两个"。

## 6. 门禁因此加强（这才是这三条不会再回来的原因）

`tools/card_text_fit_check.mjs` 从 4 条断言加到 6 条，新增的两条专治上面这类"声明了但没生效"：

1. **说明框内容盒高度必须是整行高的整数倍**（`clientHeight − padding` 对 `lineHeight` 取余 ≤1px）。
   ⚠️ 第一版这条自己写错过：拿含 padding 的 `clientHeight` 去除，把 8px 内边距算成"半行"，
   对正确的 3 行布局误报残留 7.8px。**断言本身也要被验证**。
2. **卡面各处文字都不许被裁**：既查文字块自身、也查**容器**（名牌/类型条）的
   `scrollWidth ≤ clientWidth`。容器那条是必须的 —— 文字块自己够宽、容器装不下时，
   会被卡片的 `overflow:hidden` 从右边切掉，只有查容器才看得见（缺陷 3 就是这样）。
