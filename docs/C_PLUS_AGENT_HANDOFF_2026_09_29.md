### 3.1 A01 的确切原因【已复现】

`tools/cplus_screens_check.mjs:156–157` 对 `indexOf` 结果先 `!!` 再 `>= 0`，boolean 与 0 比较恒真；后面的 OR 也不符合“两道门都满足”。不要只修括号后保留 OR。

目标表达式：`mode === 'v2' && tokens.includes(screenKey)`。由于 probe 在模板字符串里，正则经过字符串生成后必须仍为正确的空白切分；用 `String.raw` 或明确的生成后测试验证。

另一个问题：返回值字段是 `r.markerRadius`，约 `:197` 却检测 `screen.markerRadius`；当前 SCREENS 配置没有这个属性，圆角断言被跳过。应检查计算样式返回值并证明一个错误半径能被捕获。

实测 gate 探针结果：

```text
总开 v2 + 全清单       hit=true  eyebrow="REPLAY"
总开 v2 + 仅 lobby     hit=true  eyebrow="REPLAY"  ← 两处问题同时出现
总关 off + 空清单      hit=true  eyebrow=null      ← 工具仍错误通过
```

3. 统一 JS 能力判断，例如 `isArenaScreenEnabled(key)`；默认值从模板属性读取，不另建一份独立清单。
4. 关图鉴时保留旧列表体验，隐藏新增详情容器并避免留白；关排行时隐藏新增领奖台，表和查档案可用。部署／其他新增容器必须有可用旧布局兜底。
5. 两个可读性偏好为独立用户能力，可以继续跨屏生效，文档明确不受 C+ 视觉开关关闭影响。
6. 定义“配置退回”保证可用旧体验，“完整源代码回退”通过回退本批提交／补丁实现；不宣称删除 link 等于全部功能回退。用服务端模板配置重新加载做验收，不只在 DevTools 改属性。

验收：总关和逐屏关没有无样式详情块／领奖台残留；其余屏不受影响；明暗与 custom 改色不改变布局模式。

### W2：先修状态一致性（A03–A07，中，依赖 W0）

**排行**：共享领奖台由“活动 tab + 请求 generation”决定；取消或忽略过期成功／失败响应。可缓存非活动榜数据，但不能更新当前领奖台。测试战绩→段位、段位→战绩、连续刷新，所有响应按反序返回。

**图鉴**：将统计加载变为明确的 idle/loading/ready/error；并发调用共享 in-flight promise；非 2xx／网络失败显示“统计暂不可用”并可重试，而不是永久统计中或静默假零。成功后更新网格与当前已选详情，保留筛选、选择和焦点。统计失败不能阻止阅读卡牌。

**部署**：按 room + 本次部署阶段维护 pending；确认前验证当前连接、阶段与六个有效唯一格。提交期间锁棋盘／随机／清空／确认；ack 成功显示等待对手；拒绝恢复可修改；超时先同步房间状态再决定能否重试，不盲目重发。退出／重连／新部署阶段清理或重建 pending。`handle_place_ships` 还服务于卡牌重摆，不能用全局“已提交一次”锁死。

**结算**：按服务端 reason 与当前视角生成唯一准确解释；仅正常击沉使用“全部战舰被击沉”。覆盖正常胜负、双方投降视角、掉线超时、操作超时、平局及未知原因。未知原因给中性结果，奖励和战绩仍取权威 payload。

**回放**：打开／退出／换 match 使 generation 递增，必要时 AbortController；所有成功、失败和 finally 更新都核对请求身份与活动屏。复现 A 慢／B 快、退出后返回、失败晚于成功、重复打开；过期请求不写 UI、不启动计时器。保持回放与观战 state／renderer 分离。

验收：以上确定性定向测试通过；既有卡牌重摆／回放帧守卫不退化。补充图鉴手机详情焦点进入、返回原卡与 Escape 行为，清理玩家界面的“卡表组件／令牌”等工程解释。

### W3：大厅、好友房、部署视觉与流程（A08，大，依赖 W1／W2）

**大厅**：中央公开等待房与可观战对局采用响应式卡片；保留在线玩家、公屏、创建房间和原好友入口。统一搜索房名／房主，状态筛选区分可加入／可观战，过滤基于现有服务端可见数据。不把等待房当对局、不展示私密房。订阅刷新时保持筛选与输入，房满／失效／权限改变返回明确错误。

**好友房**：呈现本人席位与空席／已加入者、真实房号、邀请与规则摘要。双方名称和状态只从真实房间数据取；缺字段显示等待，不伪造第二人。不新增准备协议。邀请复制失败提供页面内可选择链接，退出／解散遵守现有语义，解散会影响他人时有清楚确认。

**布船**：保留双栏，添加坐标、从同一 `gameState` 派生的六槽、清空；确认常驻，未就绪／pending 禁用并解释原因。手机棋盘可点击，不被顶栏或按钮遮住；1280×720 主确认可见。

验收：两个浏览器从真实大厅建房／加入→部署→猜拳→对局；另测房满、解散、失效、断线恢复、双击确认、第二次邀战和卡牌重摆。改 `lobby_check` 的固定三列判据时保留四类功能覆盖和可操作性断言。

### W4：图鉴、排行、档案、设置视觉收口（A08，中，依赖 W1／W2）

- 图鉴保留当前主体，改善筛选栏空间和空态，桌面详情在可用高度内滚动，手机同窗详情完整可读。沿用正式卡面比例与文字层，不替换成原型 SVG 卡。
- 排行维持两榜语义和服务端排序，优化前三名／列表／本人行。无数据、少于三人、长名字、隐藏段位都可用。不对截断的 100 人结果做“全服胜率排序”。
- 档案把**查看面**在宽屏扩成名片 + 数据／徽章／历史两栏，手机回单栏；保留同一构建器与编辑面分离，所有入口复用。没有授权时隐藏编辑操作，保存失败不假成功。
- 设置保留真实四分区和当前预览实现，统一主次按钮；验证两个可读性设置实际作用于棋盘／状态色与动效，不只验证 attribute。关闭／重开／刷新后的状态一致。

验收：图鉴功能矩阵、本人／他人档案、保存失败／成功后跨首页和查看入口同步、明暗与各主题、真实音频／壁纸／账号权限均正确。

### W5：结算、回放、观战完整收口（A08，大，依赖 W1／W2）

- 结算采用居中主视觉与三组真实数据，保留解锁／经验／段位组件。窄屏折列，异常原因与休闲／人机无排位奖励等状态自然降级。
- 增加“本局回放”真实入口：先追踪 `_finalize_match`、持久化和正常／重连结束 payload 的真实 match id。缺少权威标识时追加最小兼容字段（名称按当前代码定），确认记录已可读取与权限后启用；不读取“历史第一条”猜本局。现有多步路径保留。
- 回放桌面双棋盘在主区，时间轴与播放控件紧邻其下，右侧安排事件列表及可切换的手牌／效果信息；真实数据与 `replayComputeFrame` 保持不变。当前事件突出，可点击定位。手机单盘切换或纵向方案以可读／可达为准，不能丢手牌与错误提示。
- 观战沿用独立净化数据流，增加公开信息图例和状态摘要，保留 roster／聊天／实时连锁／场地。权限关闭、比赛结束、连接断开都有明确出口。

验收：回放首／末／任意 seek、1×2×4×、棋盘重置、卡牌伤害、船位与效果变动、失败状态、退出后清理；观战多客户端权限与隐藏信息不变量；结算本局 ID 不串局。

### W6：历史红项、完整回归与交付（A09／A10，大，依赖 W3–W5）

旧报告记录但本轮未重跑：观战 146/8、壁纸 30/3、段位榜 26/3、好友邀请 49/2；回放曾受猜拳随机失败影响。每项建立 issue 记录：复现步骤、真实根因、产品／工具／环境分类、修复及当前结果。

## 8. 必须保留的不变量【已读码／目标规格】

1. UI 消费权威数据，不重算规则；回放从 `GET /api/replay/<match_id>` 取数，不能发业务 socket 动作。
2. 回放与观战 state／DOM／renderer 隔离。`api.py:934 _replay_read_allowed` 的权限规则保留，游客／参与者／公开战绩边界不改变。
3. 观战攻击方向在既有转换处只转置一次；屏一取对方攻击，屏二同理。不得为了布局把已净化的数据再猜船位。
4. 布船接口同时涉及开局和卡牌重摆，提交锁必须限定有效阶段／会话，不永久锁死。
5. 名片查看和编辑分离，权限与保存返回值为准；设置可读性偏好、音频、本地主题、服务端隐私分别使用既有存储。
6. 保留真实卡面比例、完整说明与速阶／类型语义，手机不能靠 hover 才能读取效果。
7. 跨屏退出清理自己的定时器、请求、焦点和订阅；不关闭他人的服务／浏览器，不重置其他功能状态。
