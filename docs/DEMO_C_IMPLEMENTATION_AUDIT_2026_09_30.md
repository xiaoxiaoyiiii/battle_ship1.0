## 4. 关键差距与优先级

### P1：主对局采用了与原型不同的构图【本次读码／实测】

`static/style.css:9691` 的 §37.4 明确写出有意采用等大双盘，理由是旧布局契约与己方点格选船需求；`9698` 起的规则将两个棋盘放在同一行。本次 1600×1000 真实对局图也确认如此。

理由可以解释工程选择，但不能把这个选择算作“完全复刻”。下一轮应围绕对手盘的主视觉、己方盘的可操作性设计适配，再同步旧尺寸断言，不能仅凭旧测试要求而冻结视觉目标。预计涉及布局、己方点格交互与几何门禁，为中等以上改动。

### P2：首页入口与参考仍有差异【本次读码／实测】

`templates/index.html:188` 的 `.home-cta-row` 保留独立昵称输入与开始匹配按钮；原型是一行休闲匹配卡。真实账号首页仍显示这一行，原型的 AI 三档选择也被下拉框替代。应把登录/游客的必要输入与 C 的入口构图一起设计；预计局部模板、事件绑定及布局改动。

### P2：真实路径工具缺少对遮挡与物理点击的验证【本次实测】

原工具输出 22 PASS，但当前 `cplus_path_a-06-game.png` 实际被更新公告完全遮住。`tools/cplus_path_check.mjs` 大量使用 `Runtime.evaluate` 中的 DOM `.click()`；该方法可绕过屏幕遮挡。因此，此 PASS 证明真实服务端与客户端事件链路成立，**不证明鼠标/触摸点击能顺利完成同一流程**。

本轮另生成临时视觉取证副本 `.tmp/demo-c-audit-20260930/path_visual.mjs`：独立 profile/端口，截图前调用既有 `closeChangelog()`，其余路径不变，也为 22 PASS。它只用于取得无遮挡画面，不冒充修复了正式工具。建议正式工具主动处理公告、添加按钮中心点命中和真实坐标点击；预计局部工具改动。

### P2：工作区成果尚未形成可复现的版本交付【本次实测】

交付报告及多支 C+ 新工具为 untracked，既有源码也有 staged/unstaged 混合改动。后续按授权整理相关文件和可复跑证据，保留用户其他改动；本轮不自动提交。不能声称“部署完成”。

### P3：布船与手机回放的原型呈现尚未收口【本次读码／历史记录】

布船以六个坐标槽代替剪影；手机回放以纵向双盘代替单盘切换。功能适配存在，但视觉完全复刻仍差这两块。预计局部视觉改动及移动交互改动。

### 已被当前证据推翻的旧待办【已证伪】

勿按旧快照重新安排“重做门控、图鉴断网不能重试、回放晚回包覆盖当前内容、没有结算回放入口、没有大厅卡片、没有观战摘要、设置仍有令牌文案”。前三项当前实跑通过，其余已在源码/最新交付 §12 可确认。未新增全服排序协议是任务书明确的范围限制，也不应当作未完成业务。
