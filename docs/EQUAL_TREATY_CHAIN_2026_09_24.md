# 平等条约 × 连锁无效化（2026-09-24）

> 作者裁决：**把「平等条约」从"快照回滚"改成"连锁无效化"** ——
> 也就是把 `docs/CHAIN_ENGINE_SPEC.md` §1.2 原本的设计实现回来，
> 并**删掉整套船数变化快照**。
>
> ⚠️ 本文**不写**那张被删的 `game_effects` 键名（源码级守卫要求全仓 0 命中）——
> 下一个人若照着找，会以为那套机制还在。想找它请看 `git log -p` 里的删除 diff。

---

## 1. 为什么改（根因：过期判据对两个座位不等价）

旧实现的判据是「`game_effects` 里的一张**船数变化台账** + 回滚」。台账里记了
`round`，读的时候写 `台账['round'] != room.round ⇒ 过期、拒绝`。

**问题在 `room.round` 的推进时机**：它只在 `handle_end_turn` 里
`next_index == 0`（＝**第二个座位**交回合）时才 `+= 1`。

于是"受害方在自己回合打平等条约"这件事**对两个座位不等价**：

| 受害方坐哪 | 受害那一刻 round | 轮到受害方时 round | 旧实现 |
| --- | --- | --- | --- |
| 后手（index 1） | R | R（还没绕过一圈） | **成功** |
| 先手（index 0） | R | R+1（后手交回合时推进了） | **必被拒**「船数改变发生在上一个大回合，无法再无效化」 |

改动前的原始红证（真 pytest，未改动代码）：

```
$ python -m pytest tests/test_pingdeng_tiaoyue_chain.py::test_treaty_is_seat_equivalent -q
E   AssertionError: 座位顺序改变了 'success'：后手受害 True / 先手受害 False
E   assert True == False
1 failed
```

同一个场景的逐步实测（`.tmp/seat_probe.py`，改前）：

```
victim_is_first=False: 平等条约 success=True  '成功无效化船数改变效果'  受害方 6 艘
victim_is_first=True : 平等条约 success=False '船数改变发生在上一个大回合，无法再无效化' 受害方 5 艘
```

—— 与作者实报的那条完全一致。改后两个座位**逐项相同**（见 §3）。

## 2. 新规则（三条，判据只此一份）

1. **目标 = 栈中正下方那一项**，与「失灵！」**共用同一份**目标解析与免疫关系
   （`server._chain_negation_target`）：目标是 `看破！` / `加百列之光` ⇒ 失败；
   不在连锁里（没有正下方那一项）⇒ 失败并给出人话。
2. **只有目标"真的会造成船数变化"时才成功** —— 判据只此一份：
   `server.EQUAL_TREATY_SHIP_CHANGE_RULES`（卡名 → `(判据函数, 人话说明)`）
   ＋ 唯一消费口 `server._equal_treaty_verdict`。结算分支**不许**自己再写 `if`。
3. 成功 = `negate_target` ⇒ `resolve_chain` 把那一项标 `negated`、
   结算时**整项跳过**（不再"先结算再回滚"，所以也不需要任何台账）。

### 判据表（`EQUAL_TREATY_SHIP_CHANGE_RULES`，逐张）

| 卡 | 判据（**这一炮/这张牌打下去真的会变**） | 真实条件 |
| --- | --- | --- |
| 轰炸 | 目标行/列里**有还活着的船** | `ChainItem.targets['target_line']` 展开成 6 格 → 与对手的活船格求交 |
| 硫磺火焰 | 选定的 6 格里有还活着的船 | 同上（与轰炸共用一个判据函数） |
| 溅射 | 上一发命中格的**上下左右四格**里有会沉掉的船 | 读 `room.last_attack`（溅射自己的目标不在 `targets` 里）；**带盾的不算**（卡面：受护盾影响） |
| 疗愈 | 真的会复活 | `caster.sunken_ships` 非空（与它自己的出牌判据同一个字段） |
| 死者苏生 | 同上 | 与疗愈**共用同一个判据函数** |
| 增援 | 真的会 +1 | `_placement_blocked_cells` < 36（与放置流程同一份占位口径） |
| 滥竽充数 | 真的补得满 | 直接复用**它自己的出牌闸门** `_lanyu_requirement_reason(...) is None` |
| 神机妙算 | ★ **只判到必要条件**（还有活船可沉） | 见 §5 的未决项 |
| 绝处逢生 | 牺牲自己全部战舰（有活船就真会改船数） | 作者裁决「保持现状、可以被无效化」 |

**不在表里**（`server.EQUAL_TREATY_NOT_NEGOTIABLE`，逐条写清为什么不康）：

| 卡 | 为什么不康 |
| --- | --- |
| 恶魔契约 | 作者已裁：它造成的「牺牲」不算可被无效化的船数变化 |
| 神之宣告 | 同上 |
| 命运骰子 | 同上（摇到 6 点让对方牺牲） |
| 守株待兔 | 同上（陷阱让对方牺牲） |

另外两类**根本没有链上目标**，所以永远康不到：普通炮击（`handle_attack`）与
教皇旨意弃卡攻击（`_do_attack`）——它们是【攻击】不是连锁项，压根不进 `room.chain`。

### 删除面（`game_effects` 里那张台账的全部读写点）

## 3. 座位等价性：改动后逐项相同

同一个场景（攻击方用轰炸打沉受害方一艘船 → 交回合 → 受害方用平等条约
连锁响应攻击方的增援），只换座位顺序：

```
victim=second -> {'success': True, 'message': '将无效化增援', 'negated': ['增援'],
                  'victim_ships': 5, 'attacker_ships': 6, ...}
victim=first  -> {'success': True, 'message': '将无效化增援', 'negated': ['增援'],
                  'victim_ships': 5, 'attacker_ships': 6, ...}
equal? True
```

守卫：`tests/test_pingdeng_tiaoyue_chain.py::test_treaty_is_seat_equivalent`
（比较 success / message / 被无效化的是哪一项 / 双方船数 / `ships`）。

## 4. 逐卡真实数据（被无效化的项 / 船数 / message）

正向（目标真的会改船数 ⇒ 成功、目标效果不生效）：

```
轰炸      -> 平等条约 success=True msg=将无效化轰炸 | 轰炸 skipped=True msg=轰炸被平等条约无效化 | 受害方船数不变(2)
硫磺火焰  -> 平等条约 success=True msg=将无效化硫磺火焰 | 硫磺火焰 skipped=True | 受害方船数不变(2)
溅射      -> 平等条约 success=True msg=将无效化溅射 | 溅射 skipped=True | 受害方船数不变(1)
疗愈      -> 平等条约 success=True msg=将无效化疗愈 | 疗愈 skipped=True | 船数不变(0)、沉船仍在堆里
死者苏生  -> 平等条约 success=True msg=将无效化死者苏生 | skipped=True | 且没有开放置流程
增援      -> 平等条约 success=True msg=将无效化增援 | skipped=True | 且没有开放置流程
滥竽充数  -> 平等条约 success=True msg=将无效化滥竽充数 | skipped=True
神机妙算  -> 平等条约 success=True msg=将无效化神机妙算 | skipped=True | 且没有开宣言窗口
绝处逢生  -> 平等条约 success=True msg=将无效化绝处逢生 | skipped=True | 一艘都没牺牲(3)
```

反向（目标不会改船数 ⇒ 失败、**不消耗**、目标照常结算）：

```
轰炸(空行)        -> 失败 msg=没有可无效化的船数改变效果（目标行/列里必须有还活着的船；打在空行/空列上不沉船）
                     轰炸照常 success=True msg=轰炸成功击沉0艘战舰
硫磺火焰(空 6 格) -> 失败 | 硫磺火焰照常 success=True msg=硫磺火焰成功击杀0艘战舰
溅射(相邻格没船)  -> 失败 | 溅射照常 success=True msg=溅射攻击命中0个目标
溅射(相邻格带盾)  -> 失败 | 溅射照常 success=True msg=溅射攻击命中1个目标（盾破了、船没沉）
疗愈(无沉船)      -> 失败 | 疗愈自身也 success=False msg=没有可复活的战舰
死者苏生(无沉船)  -> 失败 | 死者苏生自身也 success=False msg=没有可复活的战舰
增援(36 格占满)   -> 失败 | 增援照常 success=True
滥竽充数(船已满)  -> 失败 | 滥竽充数自身也 success=False msg=自己的船数已满(6/6)
神机妙算(无活船)  -> 失败 | 神机妙算照常 success=True msg=请宣言预测减少的船数（0-6）
恶魔契约/神之宣告/命运骰子/守株待兔 -> 失败 msg=没有可无效化的船数改变效果（<卡名>不会造成可被无效化的船数变化）
普通炮击击沉后再打 -> 失败、船不会回来、平等条约退回手牌
```

免疫关系 / 非连锁：

```
目标=看破！      -> 失败 msg=看破！优先于平等条约，无法无效化
目标=加百列之光  -> 失败 msg=加百列之光免疫平等条约
被看破压制期间    -> 失败（出牌/响应层被拦；同一连锁里看破！先结算那一帧也拦）
没有正下方那一项  -> 失败 msg=平等条约只能在连锁中发动：现在没有可无效化的「正下方那一项」
```

## 5. 未决项（请作者裁决）

1. **★ 神机妙算 做不到"准确预判会不会改船数"**。它的改船数方式是
   「大回合结束时，若自己船数正好减少 `x`，那些船不减少并重新部署」，而
   `x` 是**它自己结算时**才开的宣言窗口里由玩家填的 —— 平等条约在连锁里
   排在它**上面、先结算**，此刻既没有 `x`、也没有基线快照；就算有 `x`，
   "这一大回合会不会正好沉 `x` 艘"也要等对方的结束阶段才知道。
   ⇒ 充分条件在这一刻**不存在**。当前判据只给出**必要条件**：
   **还有活船可沉**（一艘活船都没有 ⇒ 船数不可能再变 ⇒ 失败）。
   ⚠️ 这是必要条件、不是充分条件 —— 请在"宁可放行"与"宁可拒绝"之间选一个。
2. **绝处逢生的规格自相矛盾**：
   - 作者裁决原文：「`绝处逢生` 的自牺牲**保持现状**（可以被无效化、拉回 1 艘）—— 别改」；
   - 同一份规格的"单一实现"那节又说：「**不在表里**的卡（牺牲类、炮击、**绝处逢生**）
     也要有交代（写清为什么不康）」。
   本批按**裁决原文**实现（它在表里、可以被康）。
   ⚠️ **玩家可见差异**：新机制下"无效化"＝**整张牌被跳过** ⇒ **一艘都不会牺牲**
   （旧机制回的是 1 艘）。若作者要的是"康不动"，改一行表项 + 一条守卫即可。
3. 非连锁失败的文案 = 作者原话「没有可无效化的船数改变效果」**+ 括号里的真实理由**
   （不是逐字复刻原话；理由是"不许静默"那条教训要求的）。
