## 七、明智埋葬真实链路修复（2026-09-12 补充）

**症状**：打出「明智埋葬」后选中一张牌，**牌不进弃牌堆、自己也不摸牌**（手牌为空时界面直接报「无效的选择」）。

**实测复现**（`apply_magic_effect` → `confirm_magic_target`，即前端真实路径）：

| 场景 | 修复前 | 修复后 |
|---|---|---|
| 手牌为空（刚把明智埋葬打出去的常见情况），选牌堆第 0 张 | `{'status':'error','message':'无效的选择'}`；弃牌堆/牌堆/手牌**全部没变** | 选中的牌进弃牌堆，牌堆移除该牌，自己摸到下一张 |
| 手牌非空，选牌堆第 0 张 | 「成功」，但**埋掉的是自己手牌里的第 0 张**，选中的牌堆卡纹丝不动 | 埋的正是选中的那张 |
| 选对方手牌里的牌（前端传候选扁平下标） | `无效的选择`（对方手牌反而还在） | 对方失去该牌、该牌进弃牌堆 |

**根因**：上一批把「实现搬进 `confirm_magic_target`」时留下了**两份语义不同的实现**。真正被前端调用的是 `confirm_magic_target` 里的分支，它照抄了旧卡面描述「弃掉手牌中的第 N 张」，把前端下发的候选下标 `card_index` 当成**施法者自己手牌的下标**：

```python
# 旧代码（confirm_magic_target）
if not (0 <= card_index < len(caster.magic_hand)):
    return {'status': 'error', 'message': '无效的选择'}
room.discard_card(player_id, caster.magic_hand[card_index])   # ← 下标指向了错误的手牌
room.draw_card(player_id)
```

施法者手牌为空时该分支直接 return（既不埋牌也不摸牌）；手牌非空时埋错牌，而选中的那张（牌堆/对方手牌）从未被取出——**弃牌堆里自然不会出现它**。

**修法**：

1. 抽出共用实现 `_bury_choice_target()` + `_apply_bury_choice()`，`select_magic_target` 与 `confirm_magic_target` **两条链路共用**，从根上消除再次漂移。
2. 下标语义统一为 `(source, index)`：候选卡下发时带上**来源内下标** `index`，前端回传 `source_index` 精确定位；兼容只传扁平 `card_index` 的旧客户端；无候选表时按来源列表内下标理解。
3. **必须从原位置真移除**（`pile.pop(index)`）再进弃牌堆，否则同一张牌会同时留在牌堆/对方手牌里（对方还能再用一次）。
4. 补 `hand_updated` 同步给对方（`draw_card` 只通知施法者），并让 `magic_temp_data['candidates']` 只存**纯数据**（原先存 `MagicCard` 实例，`get_magic_temp_data` 直接 emit 会 JSON 序列化失败）。
5. 补校验：只有施法者本人、且确实存在 `type='bury_choice'` 的待选择状态时才能确认（对方不能替你选，重复点击不能二次结算）。
6. `cancel_magic_selection` 只把真正的 `MagicCard` 实例放回牌堆，避免纯数据候选污染牌堆。

**新增回归**：`tests/test_mingzhi_burial_fix.py`（21 条，含上表三个场景 + 全链路 `use_magic_card → chain_response → confirm_magic_target` + 防作弊/边界）。
基线更新：**`281 passed / 0 failed`**。

### 7.1 「摸牌效果没触发」的排查（同日追加）

修好链路后仍有「没有触发摸牌效果」的反馈，于是做了一次**真实浏览器端到端**验证
（无头 Edge + CDP：两个 socket 打完整局 → 真点手牌出牌 → 真点弹窗里的卡）：

| 观察点 | 结果 |
|---|---|
| 手牌（确认前 DOM） | `["增援"]` |
| 手牌（确认后 DOM） | `["增援","五险一金"]` ← **确实摸到了** |
| 弃牌堆 | `["明智埋葬","钢筋铁骨"]` ← 选中的牌确实进了弃牌堆 |
| 对局日志 | `第1回合 · ME 的【明智埋葬】埋葬了「钢筋铁骨」，并摸到了「五险一金」` |

也就是说**代码链路是通的**。真正会让人认为「没摸到牌」的是下面三种**规则性**情况 ——
它们原先**完全静默**，而且旧的成功提示一律写「并摸了一张牌」，属于谎报：

1. 牌堆已空（长局/反复测试本卡时很常见，每次使用消耗 2 张牌堆）→ 现在提示「牌堆已空，没能摸到牌」；
2. 「无中生有」本大回合生效（`no_draw`）→ 现在提示「无中生有生效中，本大回合无法摸牌」；
3. 摸到的牌与手牌重名（全局去重规则，`失灵！` 除外）→ 那张牌直接进弃牌堆，现在提示「摸到的牌与手牌重复，已直接进弃牌堆」。

同时补了两处**用户可见的误导**：

- 前端 `applyCardEffect` 的 `case '明智埋葬'` 原本在**连锁刚结算、玩家还没点选**时就弹
  「明智埋葬效果生效，**埋葬卡牌并抽一张新牌**」（而且双方都会看到）——玩家自然以为效果已经
  生效、牌已经摸了。改为按角色区分：「明智埋葬：请选择要埋葬的卡牌（牌堆或对方手牌）」/
  「对方发动了明智埋葬，正在选择要埋葬的卡牌」。
- `playMagicCard` 里「不是你的回合」被误报成「当前阶段 preparation 不允许使用速阶2的魔法卡」
