# Fluent 2 UI 重构（2026-09-21）

把默认主题换成微软 Fluent 2 / Windows 11 观感：Mica/Acrylic 材质、Segoe UI Variable、
4px/8px 圆角档位、#0078D4 强调色、深色跟随 `prefers-color-scheme`；旧的 6 个预设
（classic / deep / lava / cyber / dusk / aurora）保留为「旧风格」分组，与 Fluent 共用同一套组件规范。

改动全部落在 `static/style.css`（不新增样式文件）+ `templates/index.html`（head 引导脚本、
两组预设卡 DOM）+ `static/game.js`（`resolveTheme` / `applyTheme` / `initThemeToggle`）。

---

## 1. 令牌三层架构

`style.css` 开头是一层**令牌区**，以哨兵注释 `@@TOKENS-END@@` 结束（AC6 指标只统计哨兵之后的正文，
这样"令牌层里写死颜色"不会被算成正文里的裸值）。

| 层 | 例子 | 谁可以覆盖 |
| --- | --- | --- |
| **结构令牌** | `--fluent-radius-control: 4px` / `--fluent-radius-lg: 8px` / `--fluent-space-1..6` / `--fluent-text-*` / `--fluent-weight-*` / `--fluent-dur-*` / `--fluent-ease-standard` | 不随主题变；预设**不许**改 |
| **材质令牌** | `--fluent-mica-blur` / `--fluent-acrylic-blur` / `--fluent-alpha-*` / `--fluent-scrim-*` / `--fluent-elev-1..8` / `--fluent-stroke-default` / `--fluent-card-bg` / `--fluent-on-solid` | 深色态覆盖 |
| **颜色令牌（只覆盖强调色系）** | `--primary` / `--primary-600` / `--primary-rgb` / `--primary-gradient` / `--primary-50` / `--accent` / `--secondary` / `--shadow-glow` | **7 个预设唯一的差异点** |

判据（AC4）：形状令牌（圆角/间距/字号/时长）在任何预设 + 任何明暗下都相同，
所以"换主题只换颜色"是可判定的 —— 检查工具按 `(body, #find-match, #player-name, .nav)` 四个
采样点比较 `border-radius`，7 预设 × 明暗两态全部一致才通过。

**预设写法**：

```css
html[data-theme-preset="fluent"]  { --primary: #0078d4; ... }
html.theme-dark[data-theme-preset="fluent"] { --primary: #60cdff; ... }
```

（`#4cc2ff` 是深色态的 `--primary-600`，不是 `--primary` —— 2026-09-22 实测确认。）

深色变体用 `html.theme-dark[...]` 显式加**一个类**提高特异性，而不是靠源码顺序 ——
本项目历史上栽过"选预设没反应"（被后面的规则按顺序压掉）。

## 2. 明暗三态模型

优先级：**用户显式选择 > 系统偏好**。

- 引导脚本写在 `<head>` 里、**先于任何 body 内容执行**，同步读出 `localStorage.theme`
  并给 `<html>` 加 `theme-dark` 类 → 首帧就不会"先浅后深"闪一下。
- 三态：`light` / `dark` / `system`（`system` 时删掉显式值，靠 `prefers-color-scheme`）。
- 检查工具的三条断言：系统 dark → 上深色标记；系统 light → 不上标记；用户显式选 dark
  且系统 light → 仍是深色（用户优先）。

## 3. 组件层重写范围

- **字体栈**：`Segoe UI Variable Text, Segoe UI Variable, Segoe UI, ...`（标题走 Display 档），
  泛型字体排在 Segoe 之后（AC3 断言）。
- **按钮**：纯色实心（`background-color: var(--primary)`）、4px 圆角、`min-height: 32px`；
  **去掉**渐变、扫光伪元素、`translateY` 位移（悬停只换底色/阴影）。
  > 例外：`#ranked-match`（排位入口）保留金色渐变（`--fluent-gold*` 令牌），
  > 见 §7 的语义色说明；`fluent_style_check --only set` 只断言 `#find-match` 是纯色。
- **输入**：浅底 + 1px 描边，**底边始终是 2px**；聚焦时四条边一起转强调色，
  并显示 2px 焦点环（`--fluent-focus-ring-color` / `-width`，由 `:focus-visible` 画）；
  4px 圆角。
  > 原文写的"聚焦时底边加粗"不准确 —— 底边在静止时就已经是 2px，聚焦只换颜色。
  > 焦点环曾因 `input:focus { outline: none }` 排在后面而被整条压掉，2026-09-22 修（见 §8）。
- **导航**：`.nav a` / `.nav .btn.secondary` 统一 `min-height: 32px` + `--fluent-radius-control`
  （原来是 999px 胶囊）。
- **模态**：`--fluent-radius-lg`(8px) + acrylic（`backdrop-filter: blur(var(--fluent-acrylic-blur))`）+ `--fluent-elev-*`。
- **浮窗**（日志 / 预览 / 聊天）：统一 acrylic 令牌。
- **首页标题**：从 `background-clip: text` 渐变字改成**实色**（渐变字在高对比度模式下会整行消失，
  AC3 断言 `color` 与 `-webkit-text-fill-color` 都不是 transparent）。
- **棋盘/格**：只换圆角与配色，**盒模型尺寸不动**（`.board` 340px、
  `.cell` 单格 **≥42px**、`.board-wrapper { flex: 0 1 340px }` 都保留 —— 被
  `tests/test_ui_review_fixes.py` 与 `tools/ui_layout_check.mjs` 盯着）。
  > `.cell` 的实际尺寸由网格算出来（`width: 100%`）：6×6 布阵盘在 1280 宽下实测 49px。
  > 原文写"`.cell` 42px"是把它当成了固定值，判据其实是"单格 ≥42px"。

### 第 25 节「视觉增强」重写

原先是"海洋霓虹"加成：渐变流光标题、按钮扫光、全息反光。Fluent 化后整节重写为
层次（elevation）+ 描边，删掉 `@keyframes btnSheen` / `cardSheen` / `titleFlow` / `rankGoldFlow`
以及对应的 `::after` 扫光规则。

### 内联样式改类

局内角落头像浮标原先由 `game.js` 写 **36 行内联样式**（position/top/left/background/borderRadius/boxShadow/padding），
内联特异性最高 → 紧凑布局那边只能靠 `!important` 一条条压回来。改成类 `.corner-chip` / `.corner-name`，
从根上消除 CSS/JS 对抗。

## 4. AC6 指标（改前 → 改后）

口径：去掉注释后统计哨兵之后的正文；`dupSel` 只算**同一 at-rule 上下文**内重复
（跨 `@media` 的重复是正常响应式写法，不算"靠顺序压制"）。

| 指标 | 基线 HEAD | 现在 | 阈值 |
| --- | --- | --- | --- |
| 裸 `#hex` | 253 | 59 | ≤ 90 |
| 裸 `rgba()` | 426 | 21 | ≤ 180 |
| `!important` | 67 | 27 | ≤ 40 |
| 重复定义选择器 | 56 | 25 | ≤ 25 |

> 基线数字是把 `tools/fluent_css_metrics.mjs` 指向 `git show HEAD:static/style.css` 量出来的。

**`!important` 分两类**：
1. 压 JS 内联样式的（角标）——**必须留**；
2. 压同文件基础规则的（dock 面板）——改高特异性普通规则消除。

## 5. ⚠️ 最大的坑：去重脚本吃掉规则（静默）

`tools/fluent_dedupe_css.py` 的历史版本在合并重复规则时，**连规则的收尾 `}` 或整条规则一起吞掉**。
已实测踩到 6+ 处，症状是**样式静默丢失**：

- `.game-container::before` 缺收尾 `}` → **它之后的上千行规则被浏览器整段丢弃**
（结果是圆角全 0px、`#find-match` 底色退回默认灰）；
- `.screen { display: none }` 被整条删掉 → **所有 `.screen` 同时可见**，对局页被撑到 2920px
（`ui_layout_check` 从 5 项红变成 51 项红）；
- `.board` / `.cell` 的选择器头被吞 → 棋盘塌成 17px 高；
- 一个 `@media` 头被吞 → 35.7 节的窄屏导航规则变成顶层垃圾声明。

这类损坏的共同特征：**CSS 解析器不报错、页面不白屏、`node --check` 管不到 CSS**。
所以补了两个**源码级**守卫：

- `tools/fluent_css_lint.py` —— 块栈解析（不是数括号）：EOF 时栈非空 = 缺收尾 `}`；
  `}` 落在空栈上 = 多余 `}`；块身里又出现 `{` = 上一条没关。**退出码 1 = 有坏块。**
- `tools/fluent_css_diff_vs_head.py` —— 对照 `git show HEAD:static/style.css`，
  按**选择器分量**比对（组规则 `A, B {}` 不算丢失），列出"基线里有、现在没有"的规则，
  并把装饰性删除（`::after` 扫光 / 流光 keyframes）单列一栏人工确认。

**教训**：CSS 的"少一个花括号"必须用**块栈**判定，数括号平衡会同时漏报（`}` 与 `{` 数量相等但位置错）
和误报（`@media` 嵌套层级）。而且**这类工具要在改 CSS 的每一步都跑**，不能只在最后跑一次。

## 8. 2026-09-22 浏览器实测：修掉 5 处 + 清理 2 处死代码

方法：隔离库起服务（`PORT=5099` + `CORS_ORIGINS=http://127.0.0.1:5099`），用应用内浏览器
**真的走一遍**（首页 → 设置页切预设 → 人机对战 → 布阵 → 猜拳 → 对战屏），
每一步都取计算样式 + 截图互相印证；改完复跑 `pytest`／`fluent_css_lint`／
`fluent_css_metrics`／`fluent_css_diff_vs_head` 与 `fluent_style_check` 的
`set` / `presets` / `dark` 三组。

### 8.1 毛玻璃整片盖住内容（P0，`z-index: -1` 被删）

`.game-container::before`（`position: absolute; inset: 0; backdrop-filter: blur(60px)`）
少了 `z-index: -1`：本容器是 stacking context，而 `.screen` 里的标题/按钮/正文都是**静态**
定位，绘制顺序排在"定位且 z-index:auto"的伪元素**前面** —— 模糊层盖在正文上，把首页、
布阵说明、猜拳的石头/剪刀/布全糊成一团色斑；只有 `.cell`、`.modal-content` 这类本来就
`position: relative` 的元素清晰，所以光看棋盘会以为没问题。

- 来源：Fluent 那次提交 `542f2d0` 把这条规则里的 `z-index: -1` 删了
  （`git show a12cd92:static/style.css` 里它还在），同时把模糊从 14px 提到 60px。
- 证据：`docs/images/fluent/*.png` 那 6 张"验收截图"**本身就是糊的**（当时只归档、
  没人用眼睛看）；`fluent_style_check` 的"定位安全"断言查的是 `.game-container` 自身，
  `ui_layout_check` 只量几何，两者都看不见像素。
- 修：恢复 `z-index: -1`，并把绘制顺序这条写进规则上方的注释（`static/style.css` 第 2 节）。

### 8.2 预设缩略色跟着当前主题一起变（P1）

`.theme-card .theme-strip` 用的是 `var(--primary)` = **当前**预设的强调色，7 张卡会一起变色
（切到熔岩后全部变橙；Fluent 下深海/熔岩/暮光/经典是同一个蓝），5113-5117 那几行按卡片写的
覆盖等于空转，选择器没有颜色预览。

- 修：令牌区新增 `--swatch-<preset>` / `-alt`（明暗各一套，取自各预设自己的强调色），
  每张卡用**自己的**令牌；`custom`（自定义主色）没有卡片，仍走 `--primary` 兜底。

### 8.3 输入框焦点环是死的（P2）

`input:focus-visible { outline: 2px solid var(--fluent-focus-ring-color) }` 被后面的
`input:focus { outline: none }` 同特异性压掉（`.modal-input:focus` 同理）。实测：
`matches(":focus-visible") === true` 但 `outline` 仍是 `none 0px` —— 键盘用户只剩"边框变色"。
Fluent 前那版有 `box-shadow: 0 0 0 3px` + 2px outline 两重提示。

- 修：三处去掉 `outline: none`，让文件自己声明的焦点环真的画出来。

### 8.4 难度下拉的箭头：浅色没有、深色变成两个大三角（P1）

整个 `.mode-ai select` 的自绘箭头规则在 `@media (max-width: 420px)` 里。同媒体查询里的
`select.secondary { background: transparent }` 用了**简写**，与它特异性相同又排在后面，
把箭头的 `background-image` / `-position` / `-size` 一起重置：

- 浅色态：箭头整个消失（看着不像下拉框）；
- 深色态：`html.theme-dark .mode-ai select` 只补回了 `background-image`，
  于是箭头以默认 `auto / 0% 0% / repeat` 铺满整个框 —— 两个大三角压住「电脑：普通」。

- 修：`select.secondary` 改用 `background-color` 长写。实测 ≤420px 明暗两态箭头都是
  `11.2px 8px` + `calc(100% - 9.6px) 50%` + `no-repeat`；320 / 390 / 420 三档内容盒都放得下
  「电脑：普通」（`scrollWidth === clientWidth`，无横向溢出）。

### 8.5 注释吞掉两条规则 + 一条空规则白扣指标

`@media (max-width: 420px)` 里 `.start-modes` / `.start-more` 的"窄屏落单列"覆盖被上一条
注释吞掉（少写收尾 `*/`，CSS 注释不能嵌套）——从未生效；而补回来会与同上下文里的
原定义构成重复（AC6 的 `dupSel` 直接 +1 撞阈值）。另外第 1219 行留了一条**空规则**
`.start-modes { }` 当指路牌，声明体是空的，只让同一个选择器多出现一次。

- 修：实测本断点容器内容宽最大 367px（两列 180px + 12px 间隙需 372px），auto-fit 必然落单列
  → 两条兜底无事可做，删除并在原处写清结论；空规则改成注释。
- 副作用：`dupSel` 25 → **24**（指标反而更宽松了）。

### 8.6 清理：4 份从未生效的旧预设定义

第 106-145 行的 `html[data-theme-preset="lava|cyber|dusk|aurora"]`（2026-09-17 那版浅色值）
与第 4 节的同名规则**特异性相同而排在前面**，被整块盖掉。实测（浅色 + 熔岩）读到的是
`#c2410c` 而不是那里的 `#f97316` → 确认死代码后删除，免得"改了这里却没反应"。

## 9. 2026-09-22 局内界面统一（第二批）

局内是上一轮唯一没被系统覆盖的一块：首页/设置/大厅早就是 Fluent，而对战屏里还混着
渐变实心表头、金属斜面格子、发光倒计时、9/10/11/15/18/20px 一堆圆角。

**范围约定**：只统一"外壳"（颜色 / 圆角 / 阴影 / 位移 / 材质），**不动布局几何** ——
局内几何被 `ui_layout_check` 的 128 项断言钉着（棋盘尺寸、触摸下限、零遮挡、不滚动）。

### 9.1 改了什么

### 9.3 过程中踩到的两个坑（都靠门禁才现形）

1. **表头分隔线不能用 `border-bottom`**：表头高度是 `auto`，`box-sizing: border-box`
   管不住它 → 浮窗各长 1px → `compact` 横屏 664×336（`scrollH` 本来就 337 > `vh` 336，
   只差 1px）把棋盘顶出重叠。改用 `box-shadow: inset 0 -1px 0 …`，零布局影响。
2. **664×336 下 `#quick-chat-btn` 会压到一个棋盘格的角**，而"格子是否被遮挡"是
   `elementFromPoint(格心)` 判定的 —— 浮标**圆角越大**、被排除的角区越多，格心才仍然
   可点。所以这两个局内浮标统一用胶囊令牌。实测：`--fluent-radius-lg`(8px) 时
   `被遮挡=1`、门禁红；胶囊时 `被遮挡=0`、门禁绿。

## 10. 2026-09-22 战斗屏结构排查（第二批：结构级）

上一轮统一了局内**视觉语言**；这一轮查的是**结构**（谁压谁、纵向预算够不够）。
结论分两半：修好两处，另发现一处此前没人量过的严重缺陷并留下诊断。

### 10.1 修好：贴底手牌的下沿被裁掉（`body` 内边距没扣）

桌面档把 `.game-container` 写成 `height: 100dvh`，但 `body` 有 `padding: 24px 16px`
（`.screen.active` 没有，是 body 上的）—— 容器底边因此落在视口下方 24px 处，
而 `body{overflow:hidden}` 让它**滚不到**：1280×720 实测手牌 `605..743`，
下沿 23px（卡片的"速阶/类型"行）永远看不见。

- 修：`body.layout-ingame:not(.layout-compact) { padding: 0 }`（水平方向仍由
  `max-width + margin auto` 居中，x 仍是 140，观感不变）。
- 验证：`ui_layout_check` 新增「整条手牌都在视口内（上下沿都不越界）」，五个宽屏档全过；
  1280×720 实测手牌下沿 **719 ≤ 720**（修前 743）。

### 10.2 修好：1200–1439px 档漏掉了"给手牌让高度"的预留

那条媒体查询里 `.game-main-container` 的 padding 被整条重写成
`padding-left: 308px; padding-right: 8px`（为让开左侧日志浮窗），**漏了
`padding-bottom: 146px`**（上面那条规则给的"给贴底手牌让高度"），并且把内容
`justify-content: flex-end` 推到右侧、与魔法预览浮窗抢同一段横向空间。

- 修：三条 padding 写全（左让日志 308、右让预览 320、下让手牌 146），内容留在中道。
- 效果：内容不再和预览浮窗重叠；已知遮挡从 **30/36 降到 12/36**（1366×768）。

### 10.3 发现（未修）：高度 ≤800px 的桌面档，堆叠的第二块棋盘被手牌压住

给宽屏组补上"棋盘逐格 `elementFromPoint` 命中测试"后量到（此前宽屏组只查
"棋盘在首屏内 / HUD 不被盖 / 手牌可点"，这三项**都在遮挡存在时照样 PASS**）：

| 视口 | 被遮挡格子 | 遮挡者 |
| --- | --- | --- |
| 1600×1000 | 0 / 36 | — |
| 1440×900 | 0 / 36 | — |
| 1366×768 | **12 / 36** | 手牌标题 `H3` |
| 1280×800 | **12 / 36** | 手牌标题 `H3` |
| 1280×720 | **18 / 36** | 手牌标题 `H3` |

根因：桌面档的棋盘是**堆叠**的（两块），纵向需要 `2×(板+框)`；而高度 ≤800 时
棋盘区可用高度只有 ~310–360px，第二块必然伸到贴底手牌下面（修 10.2 之后仍不够）。

试过的两条路都撞契约（已回退，代码注释里留了结论）：

- **并排两块**（复用 `adaptive_layout.js` 的 `side` 模式）：纵向需求减半、尺寸还能变大，
  1600/1440 完全可行；但 1280/1366 档横向要 `2×(280+框) ≈ 640px`，而本档内容区
  可用宽度只有 ~590–680px（左右两条浮窗各吃掉一截）。
- **`tabs` 一屏一块**（紧凑档一直在用的机制）：横向够了，但纵向预算只够
  `min(W,H) - 开销 ≈ 267px`，仍然过不了宽屏组「两块同尺寸且 **>=280px**」这条。

**所以这不是能顺手改的小问题**：要修必须重新定宽屏契约（改动 `ui_layout_check`
的 `WIDE_VIEWPORTS` 断言或布局分区），属于需要产品决策的范围。现状是：
`ui_layout_check` 每次运行都会打印一行 `棋盘逐格遮挡（诊断）: [...]`（不再静默），
修完后把那行改成 `check(...)` 即可。
