# Fluent 2 UI 重构（2026-09-21）

把默认主题换成微软 Fluent 2 / Windows 11 观感：Mica/Acrylic 材质、Segoe UI Variable、
4px/8px 圆角档位、#0078D4 强调色、深色跟随 `prefers-color-scheme`；旧的 6 个预设
（classic / deep / lava / cyber / dusk / aurora）保留为「旧风格」分组，与 Fluent 共用同一套组件规范。

改动全部落在 `static/style.css`（不新增样式文件）+ `templates/index.html`（head 引导脚本、
两组预设卡 DOM）+ `static/game.js`（`resolveTheme` / `applyTheme` / `initThemeToggle`）。

---

## 1. 令牌三层架构

`style.css` 开头是一层**令牌区**，以哨兵注释 `@@TOKENS-END@@` 结束（AC6 指标只统计哨兵之后的正文，
这样"令牌层里写死颜色"不会被算成正文里的裸值）。

| 层 | 例子 | 谁可以覆盖 |
| --- | --- | --- |
| **结构令牌** | `--fluent-radius-control: 4px` / `--fluent-radius-lg: 8px` / `--fluent-space-1..6` / `--fluent-text-*` / `--fluent-weight-*` / `--fluent-dur-*` / `--fluent-ease-standard` | 不随主题变；预设**不许**改 |
| **材质令牌** | `--fluent-mica-blur` / `--fluent-acrylic-blur` / `--fluent-alpha-*` / `--fluent-scrim-*` / `--fluent-elev-1..8` / `--fluent-stroke-default` / `--fluent-card-bg` / `--fluent-on-solid` | 深色态覆盖 |
| **颜色令牌（只覆盖强调色系）** | `--primary` / `--primary-600` / `--primary-rgb` / `--primary-gradient` / `--primary-50` / `--accent` / `--secondary` / `--shadow-glow` | **7 个预设唯一的差异点** |

判据（AC4）：形状令牌（圆角/间距/字号/时长）在任何预设 + 任何明暗下都相同，
所以"换主题只换颜色"是可判定的 —— 检查工具按 `(body, #find-match, #player-name, .nav)` 四个
采样点比较 `border-radius`，7 预设 × 明暗两态全部一致才通过。

**预设写法**：

```css
html[data-theme-preset="fluent"]  { --primary: #0078d4; ... }
html.theme-dark[data-theme-preset="fluent"] { --primary: #4cc2ff; ... }
```

深色变体用 `html.theme-dark[...]` 显式加**一个类**提高特异性，而不是靠源码顺序 ——
本项目历史上栽过"选预设没反应"（被后面的规则按顺序压掉）。

## 2. 明暗三态模型

优先级：**用户显式选择 > 系统偏好**。

- 引导脚本写在 `<head>` 里、**先于任何 body 内容执行**，同步读出 `localStorage.theme`
  并给 `<html>` 加 `theme-dark` 类 → 首帧就不会"先浅后深"闪一下。
- 三态：`light` / `dark` / `system`（`system` 时删掉显式值，靠 `prefers-color-scheme`）。
- 检查工具的三条断言：系统 dark → 上深色标记；系统 light → 不上标记；用户显式选 dark
  且系统 light → 仍是深色（用户优先）。

## 3. 组件层重写范围

- **字体栈**：`Segoe UI Variable Text, Segoe UI Variable, Segoe UI, ...`（标题走 Display 档），
  泛型字体排在 Segoe 之后（AC3 断言）。
- **按钮**：纯色实心（`background-color: var(--primary)`）、4px 圆角、`min-height: 32px`；
  **去掉**渐变、扫光伪元素、`translateY` 位移（悬停只换底色/阴影）。
- **输入**：浅底 + 底边强调色，聚焦时底边加粗；4px 圆角。
- **导航**：`.nav a` / `.nav .btn.secondary` 统一 `min-height: 32px` + `--fluent-radius-control`
  （原来是 999px 胶囊）。
- **模态**：`--fluent-radius-lg`(8px) + acrylic（`backdrop-filter: blur(var(--fluent-acrylic-blur))`）+ `--fluent-elev-*`。
- **浮窗**（日志 / 预览 / 聊天）：统一 acrylic 令牌。
- **首页标题**：从 `background-clip: text` 渐变字改成**实色**（渐变字在高对比度模式下会整行消失，
  AC3 断言 `color` 与 `-webkit-text-fill-color` 都不是 transparent）。
- **棋盘/格**：只换圆角与配色，**盒模型尺寸不动**（`.board` 340px、`.cell` 42px、
  `.board-wrapper { flex: 0 1 340px }` 都保留 —— 被 `tests/test_ui_review_fixes.py` 与
  `tools/ui_layout_check.mjs` 盯着）。

### 第 25 节「视觉增强」重写

原先是"海洋霓虹"加成：渐变流光标题、按钮扫光、全息反光。Fluent 化后整节重写为
层次（elevation）+ 描边，删掉 `@keyframes btnSheen` / `cardSheen` / `titleFlow` / `rankGoldFlow`
以及对应的 `::after` 扫光规则。

### 内联样式改类

局内角落头像浮标原先由 `game.js` 写 **36 行内联样式**（position/top/left/background/borderRadius/boxShadow/padding），
内联特异性最高 → 紧凑布局那边只能靠 `!important` 一条条压回来。改成类 `.corner-chip` / `.corner-name`，
从根上消除 CSS/JS 对抗。

## 4. AC6 指标（改前 → 改后）

口径：去掉注释后统计哨兵之后的正文；`dupSel` 只算**同一 at-rule 上下文**内重复
（跨 `@media` 的重复是正常响应式写法，不算"靠顺序压制"）。

| 指标 | 基线 HEAD | 现在 | 阈值 |
| --- | --- | --- | --- |
| 裸 `#hex` | 253 | 59 | ≤ 90 |
| 裸 `rgba()` | 426 | 21 | ≤ 180 |
| `!important` | 67 | 27 | ≤ 40 |
| 重复定义选择器 | 56 | 25 | ≤ 25 |

> 基线数字是把 `tools/fluent_css_metrics.mjs` 指向 `git show HEAD:static/style.css` 量出来的。

**`!important` 分两类**：
1. 压 JS 内联样式的（角标）——**必须留**；
2. 压同文件基础规则的（dock 面板）——改高特异性普通规则消除。

## 5. ⚠️ 最大的坑：去重脚本吃掉规则（静默）

`tools/fluent_dedupe_css.py` 的历史版本在合并重复规则时，**连规则的收尾 `}` 或整条规则一起吞掉**。
已实测踩到 6+ 处，症状是**样式静默丢失**：

- `.game-container::before` 缺收尾 `}` → **它之后的上千行规则被浏览器整段丢弃**
（结果是圆角全 0px、`#find-match` 底色退回默认灰）；
- `.screen { display: none }` 被整条删掉 → **所有 `.screen` 同时可见**，对局页被撑到 2920px
（`ui_layout_check` 从 5 项红变成 51 项红）；
- `.board` / `.cell` 的选择器头被吞 → 棋盘塌成 17px 高；
- 一个 `@media` 头被吞 → 35.7 节的窄屏导航规则变成顶层垃圾声明。

这类损坏的共同特征：**CSS 解析器不报错、页面不白屏、`node --check` 管不到 CSS**。
所以补了两个**源码级**守卫：

- `tools/fluent_css_lint.py` —— 块栈解析（不是数括号）：EOF 时栈非空 = 缺收尾 `}`；
  `}` 落在空栈上 = 多余 `}`；块身里又出现 `{` = 上一条没关。**退出码 1 = 有坏块。**
- `tools/fluent_css_diff_vs_head.py` —— 对照 `git show HEAD:static/style.css`，
  按**选择器分量**比对（组规则 `A, B {}` 不算丢失），列出"基线里有、现在没有"的规则，
  并把装饰性删除（`::after` 扫光 / 流光 keyframes）单列一栏人工确认。

**教训**：CSS 的"少一个花括号"必须用**块栈**判定，数括号平衡会同时漏报（`}` 与 `{` 数量相等但位置错）
和误报（`@media` 嵌套层级）。而且**这类工具要在改 CSS 的每一步都跑**，不能只在最后跑一次。

### 工具使用注意

- `fluent_style_check.mjs --only` **只接受单个分组**（`set|presets|dark|shots`），传逗号列表会直接退出。
- `ui_layout_check.mjs` 用持久 profile（`C:/Windows/Temp/ui_layout_check_profile`）。
  **同一服务器连续跑两次**会因为上一轮的对局状态残留而假红（实测 run1 全绿、run2 在 tablet 组红）；
  **跑之前 `rm -rf` 那个 profile**，一次跑一遍。
- 本地验证端口避开 5060/5061；服务端必须带 `CORS_ORIGINS=http://127.0.0.1:<端口>`，
  否则 socket.io 静默连不上。
- 后台服务不能跨 Bash 调用存活 —— 起服务、跑工具、kill 必须在**同一条命令**内。

## 7. 未实现 / 降级项

- **Mica 真材质**（桌面窗口级采样）在浏览器里不可得，用 `backdrop-filter: blur()` + 半透明底
  **近似**（Windows 11 上观感接近；其它平台退化半透明）。
- 令牌化只覆盖到"正文里能自动识别的裸值"（三个令牌化脚本），**没有**做全量 CSS-in-JS 式改造；
  少量具名色（如 `--fluent-gold` 的语义用色）仍在令牌层里显式声明。
- 旧 6 预设只继承 Fluent 的**结构**（圆角/间距/字体/尺寸），配色仍是它们各自的强调色系 ——
  这是刻意的，AC4 只要求形状一致。
