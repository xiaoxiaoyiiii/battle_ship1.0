# 首页与顶部导航：分组化 + 层级化（2026-09-19 首页拥挤批）

> 起因：首页截图（CSS 宽约 1030px，命中 `.game-container` 的 `max-width:1000px`）被判「界面拥挤」。
> 改动文件：`templates/index.html`、`static/style.css`。**没有 JS 改动**，没有新增/删除任何元素 id。

---

## 1. 诊断：拥挤的成因不是"东西太多"，而是没有分组、没有层级、有重复

| # | 位置 | 现象 | 性质 |
| --- | --- | --- | --- |
| 1 | `.nav-menu` | 一行 11~12 个等权目标（品牌 + 登录/注册/排行榜/游戏大厅/深色模式/好友 + 帮助/设置/🎵/🎬）。文本链接（`border: transparent` 的胶囊）与描边按钮**交替出现**，视觉重量不一致，且无任何分隔 | 结构缺失 |
| 2 | `#start-screen .button-group` | 7 个语义不同的控件**同宽竖排**：匹配（1.1rem 高）/ 排位（金色）/ 人机 / **难度下拉** / 自定义房 / 大厅。三种主次形态混排；难度下拉属于「人机」却单独占一行，把模式列表打断 | 层级缺失 + 语义断裂 |
| 3 | 冗余 | ① 导航品牌「⚓ 战舰游戏」与首页 `h1` 字面相同；② 「游戏大厅」在导航与首页各一份（两者都被工具断言存在，不能删）；③ `#my-level-strip` 与 `#online-count-container` 各占一行、孤立在底部 | 重复 + 节奏松散 |

**顺手修掉的两个真实缺陷：**

1. `<select id="ai-difficulty" class="secondary">` 的 `.secondary` **完全无效** —— CSS 只定义了
   `button.secondary / .btn.secondary / .btn-secondary`，挂在 `<select>` 上不匹配任何一条，
   它实际吃的是通用 `input, select` 规则（白底方框）→ 与旁边的描边按钮**不同形态**。
2. 全局 `input, select { margin-right: 0.5rem }` 是给"同一行里跟在输入框后面的按钮"留的间距；
   首页那个输入框是**独占一行居中**的，这条右外边距让它整体**左偏 4px**（截图里肉眼可见）。

## 2. 改法

### 2.1 导航按语义分三组（视觉分隔，不动元素）

```
.nav-menu
  .nav-group.nav-main      排行榜 · 大厅 · 好友        （登录态另有 个人战绩 · 个人信息）
  .nav-group.nav-account   登录 · 注册    |   已登录：xxx · 退出
  .nav-group.nav-tools     帮助 · 设置 · 🎵 · 🎬
```

- 组间用 `.nav-group + .nav-group { border-left: 1px solid var(--panel-border) }` 分隔。
  ⚠️ **不能用 `::before` 画这条线**：第 25 节给所有 `button` 加了 `overflow: hidden`
  （hover 流光扫过用），伪元素会被整块裁掉 —— 这是"线画不出来且不报错"的形状。
- 统一 `.nav a` 与 `.nav .btn.secondary` 的 `min-height / border-radius / line-height`，
  两组此前一个带 border、一个不带，基线不齐。
- `.nav-user` 加 `max-width + ellipsis`，长用户名不再把导航顶宽。
- 文案：「游戏大厅」→「大厅」（`lobby_check.mjs` 只断言 `href="/lobby"`，不断言文案）。

### 2.2 首页拆成三块，主次分明

```
.start-modes   匹配游戏(主) · 排位对战(金色) · [人机对战 + 难度下拉 同一行]
.start-more    自定义房间游戏 · 游戏大厅
.start-status  等级条 + 在线人数（并排一行）
```

- 模式区/次级区用 `grid-template-columns: repeat(auto-fit, minmax(180px, 1fr))`，
  `width: min(100%, 640px)`：**宽屏自动两列，窄屏自动单列**，不需要额外断点。
- `#ai-difficulty` 与 `#ai-match` 装进 `.mode-ai`（flex 同一行），修掉"下拉打断模式列表"。
- 补 `select.secondary` 样式，让下拉与描边按钮同形态。
- `#start-screen` 作用域内撤掉输入框的 `margin-right`，修居中偏移。
- `h1` 文案「⚓ 战舰游戏」→「选择你的战场」：与导航品牌重复，保留 `h1` 只当视觉锚点。

### 2.3 窄屏导航：分组退化为流式（`≤560px`）

实测发现**分组本身会让小屏变高**：320px 视口下导航从 160px 长到 240px（三个分组各自独占一行）。
小屏上宽度本来就不够，分组边界只是白占三行，所以：

```css
@media (max-width: 560px) {
    .nav-group { display: contents; }   /* 分组盒子不生成，子项回到 .nav-menu 一层换行 */
    .nav-group + .nav-group { border-left: none; padding-left: 0; }
}
```

`display: contents` 让子项直接参与 `.nav-menu` 的 flex 换行，排布与改动前一致，分隔线随分组盒子一起消失。

## 6. 遗留：第二步（本次**未做**）

`#toggle-theme` 是同一个业务判断的**两份实现**（CLAUDE.md 第 10 节第 1 条）：
`index.html` 末尾内联脚本管 `html.theme-dark` + `localStorage['theme']`；
`game.js` 管 `data-theme-preset`（deep/lava/cyber/dusk/aurora/classic）+ `battleship_theme_preset`。

合并时要**同时**处理：那段内联脚本对 `#toggle-theme` **无 null 守卫**
（`themeToggle.textContent = …` 直接赋值）→ 一旦导航里删掉该元素，首页会抛 `TypeError`，
被 `ui_layout_check` 的「页面无 JS 异常」判红。
