## 1. Phase 3 · §10.3 那个"未修缺陷"实测比记录的更严重

### 1.1 先量：遮挡的真实数字

工具：`tools/wide_geometry_probe.mjs`（逐格 elementFromPoint）

| 视口 | 棋盘排布 | 第二块棋盘底 | 视口高 | 第二块**点不到的格** |
| --- | --- | --- | --- | --- |
| 1600×1000 | 并排 | 669 | 1000 | 0 / 36 |
| 1440×900 | 并排 | 669 | 900 | 0 / 36 |
| **1366×768** | **堆叠** | **991** | 768 | **36 / 36** |
| **1280×800** | **堆叠** | **1054** | 800 | **36 / 36** |
| **1280×720** | **堆叠** | 894 | 720 | **36 / 36** |

`FLUENT_UI_2026_09_21.md` §10.3 记的是「第二块棋盘被手牌标题压住 12–18 格」；
实测是**第二块整块掉出视口、36 格一格都点不到**（比记录更严重）。第一块也中 12–18 格。

### 1.2 根因（不是"高度不够"，是"被迫堆叠"）

`@media (1200px–1439px)` 里 `.game-main-container` 让出左右两块浮窗（308 + 320 = 628px），
而 `.game-container` 本身封顶 **1000px** → 532..628 那段宽度不够，内容只剩 **~306px**：

- `.board-wrapper` 基础规则是 `flex: 0 1 340px`（**由 `tests/test_ui_review_fixes.py` 钉住**），
  两个 340px 基准放不进 ~306px 的一行 → `flex-wrap` 把第二块折到**第二行 = 堆叠**；
- 堆叠需要的纵向空间是并排的**两倍**，于是第二块整块掉到视口外。

> 结论：这不是"棋盘太大"，是**宽度预算被切掉了 2/3** 导致并排退化成堆叠。

### 1.3 修法（只在本档解掉宽度上限，不动那条被测试钉住的规则）

```css
/* @media (min-width: 1200px) and (max-width: 1439px) 内 */
.game-container      { max-width: none; width: 100%; }          /* 解掉 1000px 封顶 */
.game-main-container { max-width: none; }                        /* 合并进原有规则 */
.game-content        { max-width: calc(100vw - 628px); }          /* 按视口算可用宽 */
.boards-container    { gap: 1rem; }                               /* 合并进原有规则 */
.boards-container > .board-wrapper { flex: 1 1 0; min-width: 0; } /* 等分同一行 */
#game-screen > #magic-system { left: 308px; right: 320px; }       /* 手牌条同步让位 */
```

- `flex: 0 1 340px` 的**基础规则一字未动** → `test_ui_review_fixes.py` 那条源码断言照旧绿。
- 最后一条是必须的：容器变全宽后贴底手牌条从 `x≈1` 开始，第一张卡正落在左下角
  **固定的「快捷语」按钮**底下（实测卡片中心 `elementFromPoint = qc-btn-label`，一张都点不到）。

### 1.4 修完复测

| 视口 | 遮挡（两块） | 棋盘尺寸 | 手牌可点 |
| --- | --- | --- | --- |
| 1600×1000 | 0 / 0 | 309 / 309 | ✓ |
| 1440×900 | 0 / 0 | 309 / 309 | ✓ |
| 1366×768 | 0 / 0 | 208 / 208 | ✓ |
| 1280×800 | 0 / 0 | 240 / 240 | ✓ |
| 1280×720 | 0 / 0 | 160 / 160 | ✓ |

`ui_layout_check.mjs` 的「棋盘逐格遮挡（诊断）」由 12/18/36 变成**全部"无"**。
「两块同尺寸且不过小」（1600×1000 = 309px）与其余 128 项断言**未重定、全绿**。

## 2. Phase 3 · 连锁叠牌（C 的「叠起来的一摞卡」）

- 新增 `buildChainCardEl()`：连锁条目复用 Phase 2 的**真卡组件**（`.card-art` /
  `.card-nameplate` / `.card-desc` / `.card-typebar`），并加一条「谁出的」角标
  （我方金 / 对手红）。→ Phase 7 出图后**一处接上、两处都换**。

  并顺带把 10 秒响应窗里**一直是空的** `#chain-cards-list` 填上同一套真卡
  （这正是计划里那句「`#chain-prompt-container` 改成叠起来的三张真卡 + 倒计时」）。
- ⚠️ 常驻那一摞**不能放进手牌条中间**：条高 138px、手牌卡 118px，再加 78px 的叠牌
  会被 `overflow:hidden` 裁掉（第一版实测卡落在 y≈961，条只到 899）。改成**贴条右侧的
  小叠牌**（40×56，绝对定位，`pointer-events:none`）。
- 门禁：`tools/chain_stack_check.mjs`（新）9 项全绿，含「常驻叠牌全部落在手牌条内」。
  原有的 `chain_target_check.mjs` / `chain_preview_check.mjs` 仍全绿。
- ⚠️ **出图时发现的一处真问题**：常驻叠牌原来放在手牌条**右下角**，而那里正是
  「聊天」浮窗（`position:fixed`，右贴边 300px、底 24px、高 210px）的位置 ——
  实测截图里叠牌被聊天窗盖住、只露出半张卡，而"看不见谁响应了谁"**正是这一期要修的
  问题本身**，等于没修。改成 `right: 320px`（聊天窗宽 + 12px 间隙；预览浮窗在上方不冲突），
  并在门禁里补一条**矩形相交**断言（两轴都有交集才算叠住 —— 第一版只判"有交集"，
  把"上下相邻、x 相交 0"误报成叠压）。

## 3. Phase 5.2 · 「手机改一屏一块棋盘」——**实测已经在走了，无需改判据**

计划里写「`adaptive_layout.js:135` 现在 390×844 判为 `stack`（两块 364px 上下堆）」。
实测量出来**不是这样**（`tools/board_mode_probe.mjs`）：

| 视口 | `boards-container[data-mode]` | 可见棋盘 | 格宽 |
| --- | --- | --- | --- |
| 320×568 | tabs | 1 块 | 40.8px（门禁下限 40） |
| 336×664 | tabs | 1 块 | 27px ¹ |
| 390×844 | **tabs** | **1 块** | **55.3px** |
| 430×932 | tabs | 1 块 | 61.7px |
| 664×336 横屏 | tabs | 1 块 | 46px（下限 36） |

> ¹ 336×664 的 27px 是本探针**强制布局类**下的数字，与 `ui_layout_check.mjs` 走真实
> 流程量出来的 40.8/46/55.3 不一致 —— 以真实流程那份为准（探针不设 `--stage-vh`）。

**结论**：Phase 5.2 想要的终局（一屏一块棋盘、格宽升到 55）**当前代码已经达到**，
计划里那条 `stack` 判据的描述已过时。**这一期不改代码** —— 改一个已经在正确状态的判据，
只会把 128 项断言里已绿的几条重新推红，没有收益。

## 4. Phase 5.3 · 手机大卡面（64×92 读不了 → 200×280）

- 紧凑档手牌卡只有 64×92，中文效果文字**必然读不了**（说明框在该档是 `display:none`）。
- 新增 `#preview-card-face`：选中卡后在抽屉里渲染一张 **200×280 的真卡面**
  （200/280 = **0.714**，与实体 TCG 63×88mm 同比例）。说明框在这一档**恢复显示**，
  字号 0.78rem、行数放宽 —— 这是全项目唯一需要读完整说明的地方。
- ⚠️ 踩到的坑：`.dock-panel[data-dock-panel="card"] .magic-card { 56×64 }` 的特异度是
  **(0,5,1)**，只写 `… .magic-card.preview-face-card`(0,4,1) 会被它压住 ——
  实测大卡面被缩成 56×64、比例 0.875、说明溢出 **941px**（正好复现了"读不了"）。
  规则里必须带上 `.dock-panel[data-dock-panel="card"]` 这段上下文。
- 门禁：`tools/mobile_bigcard_check.mjs`（新）7 项全绿 —— 尺寸 200×280、比例 0.7143、
  说明 `scrollHeight − clientHeight = 0`（完整显示）。
