## 2. 两个查实的问题（都不是"看着不对"，是量出来的）

### 2.1 首页的布局规则**只写在 `@media (max-width: 420px)` 里**

第一版我把新样式插在锚点文本第一次出现的位置 —— 而那处在 `@media (max-width: 420px)` 内（第 6905 行开）。
后果：AC6 / CSS lint 全绿、文件里 grep 得到，但 **1440 下浏览器里一条都不生效**
（实测 `.home-hero` 边框 0px、背景 `none`、`.tt` 仍是 `inline`）。

顺着查下去发现更根本的事：`.start-modes` / `.start-more` / `.mode-btn` / `.start-status` 的
**布局与外观原本也只有 ≤420 那一份** —— 也就是说**宽屏首页从来没有网格**，旧首页"看起来像两列"
只是行内元素自然换行。这一轮把首页布局补成了顶层规则（`.home-wrap` 作用域）。

> 教训：`python tools/fluent_css_lint.py` 只查**块平衡**，"整块落进某个媒体查询"它查不出来。
> 改一屏 CSS 之前先确认插入点的**括号深度**（本次用一段 10 行脚本算出来的）。

### 2.2 `ENABLE_TEST_EVENTS=1` 是跑对局类工具的**前提**

`target_flow_check` / `acceptance_shots` 崩溃（`Cannot read properties of undefined (reading 'players')`）
不是工具坏了：它们用 `test_get_game_state` 这个**调试事件**，而 CLAUDE.md 写明未设 `ENABLE_TEST_EVENTS=1`
时服务端一律拒绝 → `st0.game_state` 为 undefined。
**起服务的参数写错会表现成"工具崩了"**，与代码无关。带上开关后 `target_flow_check` 全部通过。

## 3. 一处断言重定（附理由）

`tools/fluent_style_check.mjs --only set` 有两条断言把 **Fluent 的 #0078d4 写死**：

- `--primary 解析为 Fluent 强调色 #0078d4`
- `#find-match 的计算底色属于 Fluent 强调色系`

默认预设切到 `arena` 后它们必然红。但这两条**本意**是"强调色出自令牌层、且主行动用它"，
不是"默认必须是 Fluent" —— 所以改成：

1. 读**当前默认预设在 CSS 里声明的 `--primary`**（按 `data-theme-preset="X"` + 明暗态匹配），与页面计算值核对；
2. `#find-match` 的底色与**该预设声明的强调色**一致；
3. 声明值取不到时退化为"属于已声明预设的强调色集合"（仍然拦得住裸值）。

重定后 `--only set` **全部通过**。
