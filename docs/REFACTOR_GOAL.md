# Battleship 重构长期目标

目标：持续拆分 `server.py` 与 `static/game.js` 的高耦合业务，将规则、状态机、AI、攻击、卡牌和生命周期逻辑迁入职责明确的模块；迁出过程中同步修复重复实现、无效兼容层和明显的性能问题。

最终验收目标：在保持现有行为和测试契约的前提下，将 `server.py` 稳定降低到约 9000 行，并让迁出的模块拥有独立边界、可注入依赖和可测试接口。

每轮工作遵循：

1. 优先选择能整体迁出的连续职责块，避免为了减少行数制造全局变量镜像。
2. 保留必要的兼容包装，测试扫描器要求的行为入口不得删除。
3. 发现重复规则、状态写入分散或热点路径低效时，同步合并和优化。
4. 先跑相关专项测试，再跑完整回归；完整回归通过后集中提交并推送 PR 分支。
5. 继续推进下一块高价值迁移，直到达到目标行数或出现需要外部决策的阻塞。
