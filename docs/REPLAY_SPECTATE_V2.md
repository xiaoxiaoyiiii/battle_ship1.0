# 回放与观战 v2

回放与观战共用 `domain/viewing.py` 的权威投影与 `screens/viewing/` 的只读舞台。展示端不执行牌效、随机选择或胜负规则。

## 状态、顺序与隐私

- p1/p2 是稳定座位，boards.p1/p2 是棋盘所有者，攻击标记已经转到受击方；前端不能再次转置。
- context 保存实际阶段、回合、行动方、额度、胜负、待重摆和词条动态状态；rules 保存当局词条完整文案、起始舰数、骰子结果、Ban 结果与版本。
- 录像含授权的完整局面；观战由白名单另行构造，普通舰位和牌面不发送。E2 公开牌名，E3 已公开舰位对观众可见；私有侦察不因此公开。
- 观看投影只读实战状态，不能因观察而激活暴雨等规则标志。

## 录像

现有 `GET /api/replay/<match_id>` 保留鉴权、设置开关和 seats 剥离，支持版本 1、2。v2 包含 initial_state、严格递增 seq 的 events、每 32 个状态事件的 checkpoints，以及 steps/nodes 元信息。

状态事件用板块整体替换表达变化；空数组即明确清除。同一 step 可以有多个事件，不能按 step 把它们覆盖成一条。演出单独记录前导/结算卡面/落点/尾声，施法者与目标归一到座位。跳转只恢复记录状态，不重新计算游戏。

最多记录 2000 步，整局 JSON 上限为 16 MiB，录制、读取与反作弊历史共用此上限。v2 同一步会保存多次状态变化，旧版 512 KiB 会让普通长局过早截断；初始单帧仍限制在 512 KiB。整局超限时按完整步骤保留能容纳的最长一致前缀，同一步的事件不会拆开，也不把后期快照混入早期步骤。初始状态自身超限则不保存损坏录像。

v1 兼容修正炮击方向与步骤上下文。已经记录的攻击坐标和结果接入炮击演出与音效，连锁快照接入入场、成功标题、逐卡结算及无效化卡面；明确的空连锁快照会清空栈。缺失的清除记录、被覆盖的增量、未记录的词条和牌效落点不能可靠补回；界面明确标示旧版限制，不猜补历史规则。

## 观战

新增出站 `spectate_frame`：`{version:2, room_id, seq, frame, cues}`。加入/重连的 `spectate_sync.viewing_frame` 提供完整基线；迟到、重复、错房和无效帧不覆盖当前画面。名单、聊天、观众数继续使用原有通道。

ViewingService 在房间串行写入提交后录制/发布；异步连锁、交互续做、超时和终局路径也接入同一入口。炮击前导采用上一公开帧，落点后提交实际结果。观战网络失败不会回滚玩家动作。

## 播放与展示

独立本地时钟控制暂停、1×/2×/4×、逐步与跳转。连锁和牌效复用实战绘制资源；观众/回放不发送玩家动画完成 ACK。退出、换局、拖动会取消旧演出和相应音效。

音效消费实际进入的演出事件，倍速跨帧和减弱动态不会漏掉炮击或连锁声音；沿用全局静音及音量，观看页可直接切换音效。连锁成功标题和单卡结算分别采用实战时长，无效化结算保留反制卡名称。

进度条按关键节点等距排列，点击标记可直接跳转；节点之间支持连续拖动与键盘定位，当前节点会保持在时间线可见区域。手牌桌面为 80×120、手机为 58×87，长手牌横向浏览；悬停或键盘聚焦显示与实战相同的大卡图、速阶、类型和完整说明，手机点击查看详情。观战仍只为本局已经公开的牌面提供预览。

共享棋盘默认允许实战交互，回放和观战显式传入只读；只读边界同时覆盖鼠标与键盘，不能影响实战攻击或选格。

终局事务可能早于实战牌效尾声保存录像；播放器使用已经记录的效果描述和终局权威状态完成尾声，不重新判断牌效结果，不补造隐藏落点。

实时队列最多 32 个待播任务或累计 8 秒演出，超限跳过过期装饰、恢复最新权威帧。减少动态效果仍呈现状态和文字结果。

舞台为双方共用容器、中线和定位的连续海域。为保证 320×568 的操作可见性，手机也采用双盘并列，棋格只读并避开全局触控最小尺寸；实际玩家棋盘的触控设置保留。
