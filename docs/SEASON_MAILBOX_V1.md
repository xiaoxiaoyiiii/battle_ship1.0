## 1. 排位赛季

### 1.1 与通行证同季、季末锁榜

- 排位季与通行证季**同时开始、同时结束**；赛季配置以通行证季配置为唯一来源。
- 到达赛季结束时刻即锁榜：该季成绩、段位、最高段位冻结，不再接受本季对局写入；排行榜标记为已锁定。
- 锁榜动作由服务端在赛季边界自动执行（首次访问/心跳触发的对账），运营无需手工操作。

### 1.2 季末奖励三档

按**本季最高段位**所在档发放（最高段位在季中逐场累计，不回退）：

| 档位 | 段位区间 | 徽记 | 外观 | 称号 |
| --- | --- | --- | --- | --- |
| 下三段 | 二级水手 / 一级水手 / 水手长 | 1000 | 卡背「深海远征」 | 赛季启航者 |
| 中三段 | 三副 / 二副 / 大副 | 2500 | 卡背「深渊网格」 | 赛季领航者 |
| 上三段 | 轮机长 / 船长 / 大舰长 | 5000 | 指针特效「日蚀脉冲」 | 赛季镇海者 |

- 发放通道：**只走邮箱附件**（不直接入账、不弹窗直发）；玩家需在邮箱里点「领取」。
- 三档数额与外观/称号 ID 以源码常量为准；如后续新增孤儿资源，只替换外观/称号，不改徽记数额与档位规则。

### 1.3 十场门槛

- 上季（上一赛季）**排位场次 < 10**：不发季末奖，软重置按下三段入口安置（即归到二级水手起点）。
- 场次统计口径为排位对局（休闲/人机/自定义/观战/回放不计入）。

### 1.4 软重置表（新季开局，无定位赛）

| 上季段位档 | 落点 |
| --- | --- |
| 下三段（0–2 档） | 压到**本大段最低小段**入口（段位不变、分数回小段起点） |
| 中三段（3–5 档） | **降一大段**，落到前一大段入口 |
| 上三段（6–8 档） | 统一回到**中三段最高档**入口（大副起点） |

- 重置后分数 = 落点档入口分（每小段 100 分）；`is_admiral` 清零。
- 上季场次 < 10 的账号同样按上表第一行落到三段最底。
- 重置在下季开始的同一事务中完成；新季首日登录即看到新段位，无需额外操作。

### 1.5 Ban 档联动

- Ban 数量按**重置后的当前段位档**决定：下三段 0 张、中三段 1 张、上三段 2 张。
- 赛季切换后玩家进入下一局时即按新档生效，不需要额外配置。

## 2. 玩家邮箱时效

| 项目 | 规则 |
| --- | --- |
| 邮件保留 | 未领取邮件 **30 天**后过期，附件作废（邮件本身也不再展示） |
| 领取后保留 | 领取成功的邮件再保留 **7 天**，期间可回看、可手动删除 |
| 季末奖附件截止 | **新赛季开始起 14 天**内必须领取，超期附件不可领（邮件正文也提示这一点） |
| 领取幂等 | 同一封邮件重复点「领取」不会重复入账，第二次返回「已领取」 |
| 已读/未读 | 首次打开或领取即标记已读；未领取附件在入口显示角标 |

- 运营群发邮件（第 3 节）默认 30 天过期、附件 30 天内可领；季末奖邮件按上表 14 天附件截止。
- 过期与不可领状态由服务端判定，前端只展示结果；玩家无法通过刷新绕过。

## 3. 管理邮件（运营发放）

入口：管理员账号在后台调用 `POST /api/admin/mailbox/send`（非管理员返回 403）。

三种收件范围：

| 范围 | 参数 | 说明 |
| --- | --- | --- |
| 全员群发 | `audience: {"kind":"all"}` | 投递给当前全部账号 |
| 条件群发 | `audience: {"kind":"condition","min_rank_tier":…,"max_rank_tier":…,"min_level":…,"max_level":…}` | 段位档 0–8、等级 0–101；至少给出一项条件，下限不得高于上限 |
| 单发 | `audience: {"kind":"single","user_id":"…"}` | 指定账号，账号不存在时报错不投递 |

幂等与校验：

- 每封管理邮件必须带**发送编号 `source_key`**（1–100 字符）。同一 `source_key` + 相同内容重复提交 → 返回「已发送」（`delivered: 0, already_sent: true`），不会重复投递。
- 同一 `source_key` 但内容或发件人不同 → 直接报错「发送编号已经用于另一封邮件」，需换编号。
- 其他校验：标题 ≤ 80 字、正文 ≤ 5000 字、附件 ≤ 10 项；徽记附件 1–100000 整数，外观/称号必须是现有资源 ID。
- 投递失败与领取异常写错误日志（第 5 节），日志里带 `actor`、`recipients`、`source_key`、`user_id`、`mail_id`。

## 4. 豪华轨（过渡方案）

- 真支付未接入前，豪华轨用 **3000 潮汐徽记**一次性购买；余额不足提示「潮汐徽记不足，需要 3000 枚」。
- 购买同一季重复下发不会重复扣费（按购买流水幂等）；这是临时过渡价，正式支付接入后另行定价，不在本说明范围。

## 5. 错误日志

- 环境变量 `ERROR_LOG_PATH`，默认 `.tmp/logs/errors.log`。
- 只收 WARNING 及以上：登录失败、对局创建失败、结算错误、邮件发放/领取失败、备份失败等；JSON 结构化，单文件 5 MB 轮转、保留 4 个历史文件。
- 排查顺序：先看该文件里 `logger.exception` 的堆栈，再对时间点查数据库与对局记录。

## 6. 数据库备份

- 环境变量 `BACKUP_DIRECTORY`；**不配置时默认为数据库文件同目录下的 `backups/`**。
- 策略：每 **7 天**做一次在线快照（SQLite `backup` API，只读源库），文件名 `weekly-<时间戳>-<随机>.db`，写入前做完整性检查（`quick_check`），成功后**只保留最近 4 份**；失败只记日志，不影响对局。
- 运营核验：看 `backups/` 目录里 `weekly-*.db` 数量 ≤ 4、最新一份时间戳在 7 天内；恢复时停机替换，勿直接覆盖生产库。
