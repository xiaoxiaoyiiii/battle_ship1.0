## Problem Statement

玩家今天打开的是一个被重写得很干净、但仍然不知道自己该看哪里的页面。

**登录入口是死路。** 首页、设置、名片里的「去登录 / 前往登录」都链到同一地址，而服务端把这个地址直接 302 回首页——全站没有登录或注册表单。游客永远无法登录，于是排位、观战、回放历史、隐私设置这些「登录后才存在」的功能全部锁死；界面还在用「登录后可保存段位与战绩」反复承诺一件玩家做不到的事。

**顶栏把 11 条路由全部平铺。** 除了首页、大厅、排行、档案、设置，连布船、猜拳、对局、结算、回放、观战这些流程内屏也各占一个一级入口。玩家可以在没有对局时点进「对局」看到一句空态，也可以在对局中一键跳走。设置与「开战」同层；手机宽度下品牌行加两行链接吃掉首屏约五分之一。

**对局屏的重心仍然是错的。** 两块棋盘一样大、并排摆放，每回合真正要操作的「对手海域」和只用来查看的「己方海域」拥有同等视觉权重；棋盘区上方还有一条 82px 的空带，右下方留白。回合没有倒计时，服务端 90 秒后会替玩家自动走一步，而玩家在那一刻之前毫不知情。轮到谁、攻击顺序、超时会发生什么，全靠玩家自己反推。右下角并排 5 个按钮，任一时刻至少 3 个是灰的——「一屏一个主行动」没有落地。

**手牌在视觉上已经不可读。** 48 张卡都有整张卡面图，而有美术的卡会把名称、速阶、类型、说明整层隐藏，只剩一张 96px 宽的图；说明文字实际约 4px，只能靠鼠标悬停的 title。触屏玩家看不清也悬停不了。出牌仍要连点两次（需要选目标的卡三次），第一次点选没有「再点一次出牌」的提示，选中后也没有取消出口；不能出牌的原因不在卡面上。

**点击仍然会静默。** 不是我的回合、这一格已经打过、当前阶段不能开炮——点对手棋盘时这些情况仍然完全静默，格子上只有 aria-disabled。只有「正在选目标」这一种会就地报错。

**连接状态不存在。** 对局通道与结算通道都不监听断开，前端从不发送重连请求；掉线后棋盘与血量照常显示，玩家以为还能操作，点下去只得到一句「操作失败」。对局 store 里的连接标记只有定义、没有任何赋值点。同一件事还会出现两条提示：服务端先推一条 error 帧，操作的回执里再回一条同样的错误。

**结算页在说谎。** 「再来一局」和「返回首页」调用的是同一个函数，都回首页——「再来一局」不会再来一局；「返回大厅」这个动作根本不存在。未知数据仍显示成一串「—」。对手名字只是文本，不能加好友、不能进档案。

**浮层与焦点是坏的。** 图鉴浮层声明自己是对话框，但打开后焦点从不进入，按 Esc 实际无效，Tab 能穿到背后页面；匹配成功浮层没有 Esc/点遮罩关闭；图鉴在根层，会盖住被关在应用壳层里的匹配成功浮层——排队时打开图鉴，匹配成功后玩家看不到倒计时与对手信息，5 秒后被直接带进布船。每次路由切换还会在文档流里插一行「正在切换界面…」，把整屏内容向下推再弹回。

**外观与可访问性没有入口。** 全站只有一套写死的深色紫色调色板；设置只有音效、回放、观战、隐私、密码、壁纸六组，没有「外观」、没有「关于」。没有减少动效、高对比、字号三档，也没有 prefers-reduced-motion 兜底。手机首屏多个控件只有 32–34px：人机难度、大厅筛选、对局棋盘标签、对局操作按钮。回放与观战在手机上仍是两块棋盘纵向堆叠，没有视角或标签切换；「退出回放」固定回首页，「返回排行榜」固定回排行榜，不管玩家从哪里来。

**该找到的东西找不到。** 图鉴仍只是首页「更多入口」里的一个次级按钮，没有一级入口；从手牌打开当前这张卡做不到。规则帮助随旧前端一起消失，新玩家没有就地解释，也没有首局引导。布船与猜拳大部分已经做好（舰位槽、随机/清空、未满禁用、三卡等大、结果一句话），但仍看不到对手是否已准备、是否在线；一方不动，另一方只能无限干等。界面上还出现了「P4 · 布船」「服务端没有选择倒计时」这类只有开发者看得懂的字符串。

这些不是「审美问题」，是**玩家无法建立因果**：我点了什么、发生了什么、现在轮到谁、我还能做什么、为什么不行。新栈把旧实现里最刺眼的一次性缺陷修掉了（不可点的 hero、强制起名、自动弹公告、匹配成功死屏、布船无槽位、排行榜无领奖台），但那条「玩家能自己走完一局」的路仍然断在登录、对局反馈、连接恢复、结算出口和移动端这五处。

## Solution

把「功能清单」重做成「一条玩家能自己走完的路」，并用一套新的视觉语言让状态一眼可读。五个承诺：

1. **登录可达。** 游客在任何一屏都能打开登录/注册浮层；登录成功后就地生效并回到原屏；排位、观战、回放、隐私不再有走不通的死链。
2. **一屏一个主行动。** 每屏视觉最重的元素就是可点的那个动作；不再出现「看起来像按钮、点了没反应」的装饰块；流程内屏不在顶栏出现。主行动在 320×568 首屏内完整可见、可点。
3. **状态永远在眼前。** 回合、阶段、剩余攻击、回合计时、先后手、连接状态、对手是否在动，集中在一条状态带里；玩家不需要猜「现在是不是我」。
4. **每次点击都有回执。** 成功、失败、为什么失败、下一步能做什么，都在页面内用一句人话说出来；不允许静默返回，不允许只有 hover 才能看到的理由，不允许同一件事出现两条提示。
5. **教学出现在需要它的那一刻。** 首局三步就地提示（摆船 → 猜拳 → 开炮），可跳过且只出现一次；手牌详情能打开这张卡的完整说明并能跳到图鉴；规则帮助随时可达但永不挡路。

### 新的视觉语言：「深海作战室 / 航图」

放弃现在的高饱和紫色与霓虹辉光，改成冷静、功能性、像作战指挥台的方向：

- **基底**：深海青黑（近黑青），叠一层极淡的航图网格与声呐弧线；装饰不进入文字背后，不参与阅读。
- **三层表面**：海面（页底）/ 甲板（面板）/ 舱室（抬升层），只用 1px 细线与明度差分层，不靠大面积阴影和渐变。
- **语义色**：琥珀＝可行动；青＝己方与信息；珊瑚红＝敌方与伤害；海绿＝成功与恢复；石板灰＋斜纹＝禁用。颜色永远不是唯一编码：速阶同时用 1–3 个实心点 + 「速阶 N」，命中/未命中同时用图标 + 文字。
- **字体与信息层级**：系统中文字体栈；数字等宽（伤害、回合、分数、倒计时）；标题 24–28，正文 15，辅助 12；去掉装饰性英文 kicker（ENTER、RANKED、P4）与内部代号，换成中文分区标签。
- **卡牌语法**：卡面保留可读文字层；速阶点阵 + 文字、类型线性图标 + 中文、场地魔法双线边框、判定魔法顶部虚线；禁用卡加 45° 斜纹并在卡面内写出原因。
- **三套主题**：深色「航图」（默认）、浅色「航海日志」（纸图底色，同一套语义色加深到正文 4.5:1）、高对比「夜航」。切换即时生效并记住选择。
- **动效**：180ms 的功能性过渡，只在状态变化时发生；命中反馈 120ms；禁止无限循环的呼吸光。减少动效模式下只保留透明度变化。

### 各屏的新样子（玩家视角）

- **首页**：一张「开始游戏」主卡（整卡可点），下面按优先级排列休闲（默认）、排位（显示当前段位与「会改变段位」）、人机（四档胶囊）、自定义房间/大厅（次级）。游客不需要起名，自动获得「舰长 1234」；登录是一个随时可点开的浮层。右侧保留段位进度、最近战绩、在线情况，但不再和主行动抢焦点。公告不遮挡、不自动弹。
- **大厅**：主行动是「快速匹配」和「创建房间」；房间卡片显示房主、人数、模式、是否可加入；自己的房间显示「解散」而不是「加入」；空列表给一句「还没有房间，开一桌或快速匹配」并带按钮；在线玩家、公屏、进行中的对局可折叠。
- **布船**：一个大棋盘 + 6 个舰位槽 + 「随机摆放 / 清空重来」；点格子放置、再点取消；「确认放置」固定在底部，未摆满时直接写「还差 2 艘」；看得到对手是否已准备/在线，等待时可以离开房间。
- **猜拳**：石头/剪刀/布三张等大的可点卡，选中态明显；结果用一句话说清谁先手，并提示先手抽 1 张、后手抽 2 张；等待时看得到对方状态。
- **匹配成功**：保留 5 秒自动进入，但「立即进入布船」始终可点；倒计时与对手信息在同一浮层内完成，且永远在最上层。
- **对局**：对手海域是唯一的大棋盘；己方海域缩成小地图 + 6 个舰位点，可点开放大；顶部状态带显示回合/阶段/攻击次数/回合计时/先后手/连接状态；手牌固定在底部且卡面可读，单击看详情、点「使用此卡」或再点一次出牌，禁用原因写在卡上；连锁只用一块居中浮层，显示牌堆、剩余秒数、以及「不响应会怎样」；日志与聊天收进抽屉，默认不占棋盘空间；非法点击当场给出回执。
- **结算**：第一眼是胜负，其次是段位变化、经验、本局关键数据；「再来一局」真的按本局模式重新排队/再开一局，「返回大厅」与「返回首页」是不同动作；段位/经验动画可跳过；本局回放入口就在手边；可加对手为好友；未知数据不显示，而不是一串「-」。
- **回放**：一块主棋盘 + 「我的视角 / 对手视角」切换 + 带关键节点的时间轴；手机同构，不再纵向堆两块盘；退出回到来时的屏。
- **观战**：桌面看双方棋盘，手机用标签切换；公开信息有图例；退出回大厅；游客看到登录提示与登录按钮，而不是隐藏入口。
- **图鉴**：一级入口（复用根层浮层，不新增路由）；搜索、筛选、点开完整卡面与说明；从手牌详情可以直接跳到当前这张卡。
- **排行/档案**：前三名领奖台、我的名次固定可见；榜单单行可点进档案；档案里的返回回到来路，徽章、战绩、回放入口按最近使用排序。
- **设置**：按「外观 / 声音 / 账号与隐私 / 关于」分组，改完立即生效；三套主题；减少动效、高对比、字号三档；公告、帮助、版本信息在「关于」里。
- **全局反馈**：一个提示队列，同一件事只出现一条；失败提示 = 原因 + 下一步；断线时全站顶部出现「正在重连」并禁用会失败的操作，重连成功后回到原屏。

## User Stories

**登录与身份**

1. 作为游客，我希望首页和头像菜单里都有一个能用的「登录 / 注册」入口，以便不被死链挡住。
2. 作为游客，我希望点「去登录」当场打开登录浮层，而不是跳回首页。
3. 作为新玩家，我希望在同一个浮层里切到注册，注册成功即成为登录用户。
4. 作为登录失败的玩家，我希望看到「用户名或密码错误 / 操作太频繁」这类具体原因，而不是静默或技术串。
5. 作为刚登录的玩家，我希望登录后回到刚才那一屏，段位、战绩、排位入口立刻可用。
6. 作为玩家，我希望登录成功后不用自己刷新页面就能生效。
7. 作为已登录玩家，我希望头像菜单里有「退出登录」，退出后回到游客状态。
8. 作为游客，我希望界面明确写「游客状态：登录后保存段位与战绩」，并知道哪些内容不会被保存。
9. 作为玩家，我希望游客名字只出现一种叫法（舰长 1234），不再首页叫「游客」、对局叫「玩家」。
10. 作为玩家，我希望改密码仍在设置里，并有成功/失败回执。
11. 作为排位入口的访客，我希望看到「需要登录」并一键打开登录浮层，而不是被拒绝后无路可走。
12. 作为观战/回放/隐私设置的游客，我希望看到登录提示和一个登录按钮，而不是入口消失。

**壳层与导航**

13. 作为玩家，我希望顶栏只保留「开战 / 大厅 / 图鉴 / 排行」四个目的地，一眼知道去哪。
14. 作为玩家，我希望设置、帮助、公告、主题、声音、战绩、档案都收进头像菜单，不再和「开始」抢注意力。
15. 作为玩家，我希望好友入口保留为图标并显示未读角标。
16. 作为玩家，我希望当前所在页面在导航里有明确高亮。
17. 作为玩家，我希望布船/猜拳/对局/结算这些流程内屏不在顶栏出现，避免误入空屏或中途跳走。
18. 作为对局中的玩家，我希望顶栏收成最小工具条，只留退出/设置，退出前确认会中断对局。
19. 作为手机玩家，我希望导航最多两行，首屏能看到主行动。
20. 作为键盘玩家，我希望 Tab 顺序与视觉顺序一致，Esc 能关闭任何浮层并把焦点还给触发按钮。
21. 作为玩家，我希望任何屏切换都先关闭上一屏的浮层，不会叠在下一次操作上。
22. 作为玩家，我希望浮层打开时背景不可操作，且同一时刻只有一层浮层。
23. 作为玩家，我希望路由切换时页面内容不因「正在切换界面」提示条而上下跳动。
24. 作为玩家，我希望全站术语一致（海域、战舰、速阶、判定、连锁、场地魔法、弃牌堆）。
25. 作为玩家，我希望按钮文案是「动词 + 对象」（开始匹配、确认放置、使用此卡），不再看到 ENTER/RANKED/P4 这类装饰或内部代号。
26. 作为玩家，我希望公告是首页/大厅里一行可关闭的提示或面板，不遮挡操作，也不自动弹窗。

**首页与开局**

27. 作为玩家，我希望首页视觉最重的块就是「休闲匹配」，整块可点。
28. 作为玩家，我希望首页不再有「看起来像按钮、点了没反应」的装饰块。
29. 作为玩家，我希望每个模式都写清条件（是否计段位、是否需要登录、大概多久）。
30. 作为玩家，我希望排位入口显示我当前段位，并标注结算会改变段位。
31. 作为游客，我希望点排位时先看到登录浮层，登录后继续排位。
32. 作为玩家，我希望人机难度是四个可直接点的胶囊（简单/普通/困难/大师），不是下拉框。
33. 作为玩家，我希望「自定义房间 / 大厅」在次级位置，不与主行动等重。
34. 作为玩家，我希望首页能力卡片/热门卡可以点开看完整卡面与说明。
35. 作为玩家，我希望排队中看到已等待时长，并能一键取消。
36. 作为玩家，我希望取消排队立刻生效并有回执。
37. 作为玩家，我希望匹配成功后看到对手信息和「立即进入布船」，不必等满 5 秒。
38. 作为玩家，我希望匹配成功浮层永远在最上层，不会被图鉴/设置等其他浮层盖住。
39. 作为玩家，我希望排队失败时提示原因（未登录/已在队列/服务器忙）与下一步。
40. 作为回访玩家，我希望首页直接显示段位、等级经验和最近战绩。
41. 作为玩家，我希望首页在线/队列数字在加载时显示「加载中」而不是「—」，空时显示「暂无」。

**布船、猜拳与等待**

42. 作为玩家，我希望布船页用 6 个舰位槽显示已放置的船，而不是只有一个数字。
43. 作为玩家，我希望页面一开始就说明「再点一次可取消」。
44. 作为玩家，我希望有「随机摆放」和「清空重来」。
45. 作为玩家，我希望未摆满时「确认放置」不可用，并直接告诉我还差几艘。
46. 作为玩家，我希望看到对手是否已摆好/是否在线，而不是无限干等。
47. 作为玩家，我希望在等待时能离开房间，并知道离开不会判负。
48. 作为手机玩家，我希望布船格至少 44px，确认按钮在拇指够得到的位置。
49. 作为玩家，我希望猜拳三张卡等大、可点、选中态明显。

## Implementation Decisions

### 1. 壳层与信息架构

- 顶栏目的地收敛为四个：开战、大厅、图鉴、排行；加一个好友图标（带未读角标）与一个头像菜单。11 条冻结路由一个都不删、不改名，只是不再全部出现在顶栏。
- 头像菜单分三组：「我的」（名片、战绩、成就、收藏）、「外观与声音」（主题、动效、字号、音效、壁纸）、「帮助与关于」（公告、玩法、版本、登录/退出）。游客与登录用户共用同一个壳层，菜单第一项在游客态是「登录 / 注册」。
- 流程内屏（布船、猜拳、对局、结算）进入沉浸模式：顶栏收成最小工具条，只保留退出与设置；退出必须确认会中断对局，并说明是否判负。回放、观战不再占顶栏，从大厅、结算、档案进入。
- 浮层统一由一个根层管理器负责：同一时刻只允许一层；打开时锁焦点、Esc/遮罩关闭、关闭后焦点归还触发者；切路由先关闭全部浮层；层级令牌保证匹配成功浮层高于图鉴。图鉴浮层改为真正的对话框语义。
- 路由切换不再在文档流里插入文字提示；加载态改为屏幕内的骨架或不占位的状态，避免布局跳动。
- 新增控件的交互契约仍用 data-testid（命名沿用「屏-控件」），现有 testid 不改名；同时更新仓外逐屏静态契约的必需 testid 清单。

### 2. 视觉令牌与主题

- 以「深海作战室 / 航图」重写设计令牌层，替换当前唯一一套深色紫色调色板。令牌分：三层表面（海面/甲板/舱室）、角色色（可行动/己方/敌方/成功/警告/禁用）、文本三级、边框、圆角、间距、动效时长。
- 三套主题：深色「航图」（默认）、浅色「航海日志」、高对比「夜航」。主题挂在根元素上，切换即时生效并持久化；系统 prefers-color-scheme 只决定首次默认。浅色不是深色反相：同一套语义色单独调对比度。
- 排版：系统中文字体栈，数字启用等宽数字；标题 24–28、正文 15、辅助 12；移除装饰性英文 kicker 与内部代号。图标改为内联线性 SVG，不再用 emoji 承担主要功能入口。
- 卡牌组件重做：卡面保留可读文字层（名称、速阶点阵+文字、类型图标+中文、说明），美术作为背景而不是替代文字；桌面 118×165、手机 64×92 两档都保证卡名与速阶可读；场地魔法双线边框、判定魔法顶部虚线、禁用卡 45° 斜纹+卡面内原因。
- 当前仓库约定「视觉改动只动颜色/阴影/渐变/transform/opacity，不动盒模型」适用于日常视觉微调；本次重设计**有意**改变布局与盒模型，因此旧几何断言与截图指纹必须成批重定基线，不能为了变绿删判据。

### 3. 登录 / 注册浮层

- 不新增路由：登录/注册是一个 App 级全屏浮层，从头像菜单、首页「去登录」、排位/观战/回放的登录提示处打开，支持「登录 / 注册」两个标签。现有 /login 与 /register 的 302 行为保持不变（只保证旧链接不 404），不再被界面直接跳转。
- 复用已经存在的 JSON 契约：POST /login 与 POST /register 接受 JSON，成功返回用户对象并设置会话 cookie，失败返回结构化错误（code/message/field）。不新增 HTTP 路由、不改 socket 事件。
- 成功后必须在原地刷新页面（socket 握手以会话 cookie 取身份），刷新后回到当前路由；登录浮层内关闭不做任何状态清理。
- 错误码映射成玩家可读文案：缺字段、用户名或密码错误、用户名已存在、操作太频繁（说明等多久）、服务器错误（可重试）。注册成功即登录；不要求邮箱等额外字段。
- 退出登录走现有 /logout 跳转；游客态显示统一的自动名字（舰长 + 4 位数字），首页展示与对局提交使用同一个名字，不再出现「游客 / 玩家」两个叫法。
- 修改密码保留在设置「账号与隐私」组，复用现有接口；登录/注册浮层不承担改密。

### 4. 首页

- 主行动是「休闲匹配」整卡可点（现状已满足），移除它下面那块看起来像按钮的虚线条提示；主按钮文案为「开始匹配」，不再用 ENTER 装饰。
- 模式区：休闲（主）、排位（显示当前段位与「结算会改变段位」；游客点击先开登录浮层）、人机（四档难度改为可直接点的分段胶囊，不再用下拉框）、自定义房间/大厅（次级）。
- 游客不要求起名；自动名字只在头像菜单里可改。首页明确标注游客状态与登录收益。
- 在线/队列/房间数字使用统一三态：加载中、暂无、失败重试；未知值不显示「—」。
- 排队中显示已等待秒数与取消按钮；取消有回执。匹配成功浮层始终在最上层，「立即进入布船」可点，5 秒自动进入作为兜底。
- 公告保留为首页/大厅内可关闭的一行提示，点击展开详情；不自动弹窗、不遮挡操作。

### 5. 对局 HUD

- **单主棋盘**：对手海域是唯一的大棋盘（桌面最小边 ≥480px，手机占可用宽度）；己方海域缩成小地图 + 6 个舰位点，点开为居中的放大浮层。观战/回放的数据净化与只读契约不变。
- **状态带**：回合、阶段、剩余攻击、回合计时、先后手/当前轮到谁、连接状态合并为一条，桌面与手机都固定不随滚动消失；数字等宽。最后 10 秒进入警示态。
- **回合计时的唯一真值在服务端**：对局快照与每次换回合/被接受动作后的帧新增「回合截止时间（epoch 毫秒）」与「超时秒数」。客户端只做倒计时渲染；字段缺失时隐藏计时，不猜。服务端超时逻辑与自动动作不变；超时动作发生后界面明确提示「超时，已自动…」。
- **手牌**：卡面可读（见令牌层）；第一次点开详情（手机底部抽屉/桌面侧栏），点「使用此卡」或再点一次出牌；选中态有明确取消按钮与 Esc；C 卡不可用原因由同一个函数产出（渲染与点击守卫共用），直接写在卡面；禁止第二份判断。
- **目标选择**：进入后常驻横幅（选什么、取消出口），高亮合法范围；非法点击给原因；选目标期间禁止开新卡。
- **连锁**：只保留一个动态居中浮层：出牌者、卡名、顺序、剩余秒数、可响应的同速阶卡、以及「不响应会怎样」的一句话；10 秒倒计时用环形进度 + 数字。不阻断棋盘与手牌的视觉主体。
- **侧栏**：日志与聊天收进抽屉，默认只显示最近一条事件；聊天有未读点；手机「日志」按钮必须真的打开日志（现状误绑到连锁面板）。
- **反馈总线**：新增全局提示队列，所有操作结果走同一入口；按错误码在 3 秒内去重；成功用轻提示，失败用「原因 + 下一步」；容器 aria-live，不抢焦点。移除各屏各自的 notice 重复实现。
- **连接**：所有实时通道监听连接/断开；断线时全站顶部横幅「连接中断，正在重连」，禁用会失败的操作；重连后发送现有重连请求回到原对局/结算，成功后提示「已恢复」；失败给重试按钮。对局 store 的连接标记必须有真实赋值点。
- **非法点击**：不是我的回合、已打过的格、当前阶段不能开炮、没有攻击次数——全部当场给一句回执，不只依赖 aria-disabled。
- **投降**：保留二次确认，并写明后果（判负、是否影响段位）。
- ���除界面上的内部代号与实现术语。

### 6. 布船、猜拳、匹配成功与等待

- 布船保留现有舰位槽、随机/清空、未满禁用与差距文案；新增对手状态（已准备/在线/掉线）与「离开房间」出口，等待时玩家知道该继续等还是离开。
- 猜拳保留三卡等大与文字结果；新增「先手抽 1 张、后手抽 2 张」说明与等待对手状态（已出拳/在线/掉线）。
- 对手状态字段以**只增**方式加入房间同步负载；不改变布船/猜拳规则，也不新增阶段超时兜底（若要加超时属于规则变更，另行开票）。
- 匹配成功浮层保留「立即进入布船」；确保层级高于其他浮层，并在排队期间打开图鉴/设置时不被遮挡。

### 7. 结算、回放、观战

- 结算动作三分：「再来一局」按本局模式重新排队（人机则重开同难度；排位按钮副文案写「会重新排队并计分」）、「返回大厅」、「返回首页」。三者不得共用同一个处理函数。客户端在对局开始时记录本局模式与难度，不要求服务端新增字段。
- 结算只渲染已知字段；未知字段隐藏或写「暂无」，禁止成排「—」。经验/段位动画 ≤2 秒且可点跳过。
- 「本局回放」保留；「加对手为好友」复用现有好友事件与结算随附的最近对手信息，不新增协议；对手是登录用户时可进档案。
- 回放：一块主棋盘 + 「我的视角/对手视角」切换；手机同构；时间轴关键节点沿用服务端已下发数据；补齐「轰炸」标记；「退出回放」回到来路（用路由 query 或来源标记），不固定回首页。
- 观战：桌面双盘、手机标签切换；退出回大厅；游客看到登录提示 + 登录按钮（打开登录浮层）；保留「观众永不拿船位」的净化契约。

### 8. 大厅、图鉴、排行、档案、设置

- 大厅：「快速匹配」与「创建房间」并列为一级动作；房间卡片补模式（休闲/排位）与是否公开（需在房间状态里只增字段；若暂不补字段则卡片不得显示猜测值）；自己的房间显示「解散」并可二次确认；空态带 CTA；在线玩家/公屏/进行中可折叠。
- 图鉴：一级入口打开现有根层浮层（不新增路由）；搜索、速阶/类型筛选、桌面右栏详情/窄屏详情页；从手牌详情带当前卡进入并高亮；浮层具备真正的对话框焦点行为。
- 排行：前三名领奖台保留；「我的名次」固定可见需要服务端在榜单响应中一并返回我的名次（未上榜为 null），前端只渲染、不在前端重排全服榜；每行可点进档案。
- 档案：名片为身份主视觉；徽章、战绩、回放入口按最近使用排序；返回回到来路；未知字段隐藏。
- 设置：四个意图分组（外观 / 声音 / 账号与隐私 / 关于）；外观即时预览；三套主题、减少动效、高对比、字号三档；偏好持久化到本地并作用于全站；「关于」收纳公告、玩法、版本；修复「打开壁纸库」与「检查壁纸」两个按钮同动作、左栏永久高亮第一项两个缺陷。

### 9. 服务端契约（只增不改规则）

- 对局快照/换回合帧新增：回合截止时间（epoch 毫秒）、超时秒数。
- 房间同步新增：对手是否已准备、对手是否在线（或等价状态）。
- 错误事件与操作回执新增：稳定错误码字段；前端按码映射玩家文案，缺码时回退服务端原文。禁止直接展示未映射的技术字符串。
- 大厅房间状态新增：模式、是否公开（若实现房间卡片这两行）。
- 排行榜响应新增：我的名次（未上榜为 null）。
- 登录/注册复用现有 JSON 契约，不新增路由；退出走现有跳转。
- 所有 socket 入站/出站事件名、HTTP 冻结路由、11 条前端路由、身份与观战/回放安全不变量保持不变。契约模型改动后必须重新生成 schema 与前端事件类型、重算契约哈希，并在构建前校验通过。
- 不新增数据库表；回合截止时间由现有超时时刻推导，不落库。客户端偏好（主题、动效、字号）只存本地。

### 10. 分期与回退

- 第 1 期：设计令牌与三主题、壳层/导航/头像菜单、登录注册浮层、统一三态组件、全局提示队列。
- 第 2 期：首页、大厅、图鉴一级入口。
- 第 3 期：布船/猜拳/匹配等待、对局 HUD（单主棋盘、状态带、回合计时、手牌、目标选择、连锁、连接、静默点击）。
- 第 4 期：结算三分、再来一局、回放与观战布局/渲染/退出回路。
- 第 5 期：排行/档案/设置、可访问性三档、移动端触控与横向布局。
- 第 6 期：删除各屏重复的提示/三态实现，重定仓外门禁与截图基线，补玩家公告。
- 回退以「整屏/整期」为单位：每期独立提交、可整体 revert；不允许半套样式或两套令牌长期并存。开发期可保留一个服务端渲染的壳层开关（默认新壳层），上线稳定后删除。

## Testing Decisions

**什么算好测试。** 只测玩家能看见、能点到的外部行为：真实服务端、真实浏览器、真实坐标点击、真实可见结果；不调用内部函数，不断言组件名或 DOM 结构，不用「某一毫秒的 DOM 里有没有」当判据。需要判定的瞬时状态（连锁窗口、倒计时）必须在事件到达的那一刻就地记录，再断言。仓外门禁的 SKIP 不是绿色，每条 SKIP 必须有归因。

**主缝隙：扩展现有真实双浏览器全链路（cplus-path）。** 同一条真实链路：登录浮层注册 → 刷新 → 首页 → 大厅 → 人机/匹配 → 布船 → 猜拳 → 对局 → 结算 → 回放 → 首页。新增：

- 点击全部改为真实坐标输入（命中测试 + 发送输入事件），不再直接调用元素的 click()；被浮层挡住必须判失败。
- 登录：游客打开浮层 → 注册 → 页面刷新后仍在本屏 → 排位入口可用 → 退出后回到游客态。
- 五个「静默点」断言：非我回合点对手格、点已打过的格、点禁用卡、选目标时点非法格、点不可用的确认按钮——必须在 200ms 内出现可读提示。
- 转场断言：匹配成功有可点的「立即进入布船」；结算「再来一局」进入新的排队/新对局而非首页；「返回大厅」与「返回首页」落到不同屏。
- 对局断言：回合计时可见并在最后 10 秒变警示；超时后有「已自动」提示；手牌卡面文字可见（不是只有图）；选中的卡可取消。
- 断线断言：浏览器离线后出现「正在重连」并在恢复后回到原屏、有「已恢复」提示。
- 桌面 1440×900 与手机 390×844 各跑一遍完整链路；全程零 JS 异常；每次转场后无残留浮层；主行动未被任何浮层遮挡。

**次缝隙：逐屏外观契约。** 复用现有逐屏/移动端/截图指纹检查，重定判据到新设计：

- 每屏只允许一个可见主行动，且在 320×568 / 390×844 首屏内完整可见、可点。
- 无横向溢出；零叠压；触控目标 ≥44px（极矮横屏沿用 36px 放宽档）。
- 进入/离开、焦点返回、浮层互斥、零 JS 异常。
- 关键控件的可访问名称存在且与可见文案一致；浮层打开时 Tab 不穿出、Esc 可关。
- 减少动效/高对比/字号三档作用于全站（抽查首页、对局、结算、图鉴）。
- 三套主题切换后无破图、正文对比度 ≥4.5:1。

**第三层：不依赖浏览器的守卫。** 各屏静态 testid 契约（被引用但页面不存在的 testid）、新增契约字段/错误码的模型单测、构建前契约哈希校验、观战快照禁键与回放 HTTP 契约。

**必须显式重定的旧断言（不是删测试，是重述契约）：**

- 「两块棋盘同尺寸且 ≥280px」→ 改为「对手海域是主棋盘（桌面最小边 ≥480px），己方海域为小地图且可放大」。
- 固定棋盘尺寸/单格尺寸 → 改为响应式区间 + 单格触摸下限（桌面 ≥42px，手机 ≥44px，极矮横屏沿用 36px）。
- C+ 紫色调色板与旧截图指纹 → 随新令牌重定；只在确认是真实改动时重录基线（沿用既有「先看差异图再重录」的纪律）。
- cplus-path 当前不点「再来一局」、不区分结算出口的现状 → 新断言必须区分「再来一局 / 返回大厅 / 返回首页」。
- 结算「再来一局与返回首页同行为」的现状 → 新断言必须证明二者目的地不同。
- 对局屏「一屏不滚动」保留；允许新增的日志/聊天抽屉内部滚动，不允许页面滚动。
- 旧栈「TURN_TIMEOUT 只做保底动作」的行为保持，但新增「客户端可见倒计时 + 超时后回执」断言。

**先例。** 主缝隙沿用现有真实链路工具的双浏览器会话、固定账号与清理纪律；真实坐标点击沿用现有真实输入能力并替换 el.click()；逐屏契约沿用现有自校准方式（断言必须先能判错，再判对）；浮层/遮挡检查沿用现有真实 socket + Chromium 的组合。

**不做的事。** 不为内部函数补单测来「证明 UI 改了」；不为像素级还原写断言；不把随时序漂移的 AI 对局状态写进外观断言；不把测试、夹具、截图基线放进仓库。

## Out of Scope

- 游戏规则、卡牌效果、伤害计算、平衡性、AI 难度与决策；本规格只改呈现与交互。

- 数据库结构变更与线上部署；上线需另行走发布流程。
- 新增美术资源、卡面重绘、音效重制；图标使用现有能力内的线性 SVG。
- Vue/构建链重写（已经完成）、原生客户端、多语言。
- 游客转正后的账号数据迁移、找回密码流程（登录/注册界面本身在范围内）。

## Further Notes

- **本文取代旧栈版规格。** 2026-10-18 版针对已删除的 Flask + 单页前端；新栈是 Vue 3 + FastAPI，11 条冻结路由、data-testid 门禁、契约代码生成都与旧栈不同。旧版里已经不再成立的现状判断（不可点 hero、强制起名、公告自动弹窗、匹配成功死屏、布船无槽位、排行榜无领奖台、好友邀战不可用）已不再写入问题陈述。
- **登录/注册是重写遗漏，不是设计取舍。** 服务端已支持 JSON 登录与注册并下发会话 cookie；旧前端删除后，新前端没有接上表单，而 302 仍指向首页。本规格把它补回来，不新增路由。
- **核验证据（2026-10-20，main @ 421ab5c，供实施定位；行号会漂移，以 grep 为准）：**
  - 登录死路：首页/设置/名片的登录链接 + 服务端 GET /login 302；前端无登录表单。
  - 顶栏 11 条平级路由；流程内屏可直达空态。
  - 对局两块同尺寸棋盘共用同一格尺寸；无缩放；底部并排 5 个按钮。
  - 有美术的卡隐藏名称/速阶/类型/说明层；手牌卡宽 96px；出牌两击、目标卡三击；选中不可取消。
  - 非我回合/已打格/非战斗阶段点击静默。
  - 回合计时缺失；超时 90 秒后仅事后 toast；攻击顺序已下发但未渲染。
  - 断线不监听、不发送重连；连接标记无赋值点；错误帧与回执重复。
  - 结算「再来一局」与「返回首页」共用同一函数，无「返回大厅」。
  - 图鉴浮层无焦点接管、Esc 失效、可遮挡匹配成功浮层。
  - 设置无外观/无「关于」/无三档可访问性；单套深色令牌；手机多个 32–34px 控件。
  - 回放/观战手机纵向堆叠；回放退出固定回首页；档案返回固定回排行榜。
  - 布船/猜拳无对手就绪状态与离开出口；界面出现 P4 等内部代号。
- **约束**：不新增/改名 11 条前端路由；不改 socket 事件名（61 入站 / 89 出站）与 49 条冻结 HTTP 路由；观战快照白名单、回放只走 HTTP、服务端权威结算等不变量不变；测试资产继续留在仓外。
- **风险与代价**：现有 20+ 支 data-testid 浏览器门禁与 14 张截图指纹按旧几何/旧视觉断言，改版期会成批变红；这是预期的重定基线，不是回归。重定时必须保留每条断言原本要守的东西（可点、不遮挡、一屏、零异常、无横向溢出），不能为了变绿删判据。契约新增字段必须重算哈希并重跑构建，否则构建会失败——这是保护，不是障碍。
- **可交互原型**：docs/ui_demos/abyss-command-prototype.html（单文件、mock 数据），说明与评审问题见 docs/ui_demos/ABYSS_PROTOTYPE.md，截图在 docs/images/abyss_demo_2026_10_19/。原型只验证方向，不替代本规格与验收缝隙。
- **建议实施顺序**：先做第 1 期（令牌 + 壳层 + 登录 + 提示/三态），因为后面每一屏都依赖它们；不要先改对局屏，否则会在旧壳层与新令牌之间来回返工。
