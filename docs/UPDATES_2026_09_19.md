# 更新公告（2026-09-19）

> 作者原话：「新增一个公告，就是每一次小更新都会显示出这一次更新的时间和内容。
> 不要写的太专业，就写修复了什么什么 bug、更改了什么什么东西就可以。」
>
> 所以这份东西的**成功标准只有一个**：玩家扫一眼就知道"这次改了什么"，且知道"是什么时候改的"。
> 它**不是** CHANGELOG.md、不是 Release Notes、更不是提交历史 —— 那些是给开发看的。

---

## 0. 一句话设计

**公告数据只有一份**（`changelog.py`）→ 一个公开只读接口（`GET /api/changelog`）→
前端只渲染、不写死任何一句 → 有新条目时登录用户进站**自动弹一次**，之后靠入口点开看。

---

## 1. 数据（`changelog.py`）

```python
CHANGELOG = [
    {'date': '2026-09-19 18:40',          # YYYY-MM-DD HH:MM，**唯一**（也是"看过没有"的标识）
     'items': ['新增了：更新公告（就是你现在看的这个）',
               '修复了：神之宣告在船太少时不该能打出去']},
    ...                                    # 最新的在最前
]

def view(limit: int = 10) -> dict          # 截断 + **拷贝**，上限 20
def latest_date() -> str                   # 没有条目时返回 ''
```

为什么单独一个文件（而不是塞进 `server.py`）：`api.py` 要下发它，而 `server.py` 是
`from api import app` 的 —— 写进 `server.py` 会让 `api.py` 反向依赖它、成环。
这与 `quick_chat.py` / `ranks.py` / `leveling.py` 是同一套路。

## 2. 接口（`api.py`）

```json
GET /api/changelog?limit=10            // **公开，不要求登录**（登录页上的人也该看得到）
{"status":"ok","latest":"2026-09-19 18:40",
 "entries":[{"date":"2026-09-19 18:40","items":["修复了：…"]}]}
```

`latest` 专门给前端判断"有没有新公告"（与 `localStorage` 里存的值比对），**不要**让前端拿
`entries[0].date` 自己算 —— 一个字段解决一件事，省得两处口径。

## 3. DOM 契约（冻结 id）

| id / class | 用途 |
| --- | --- |
| `#changelog-btn` | 首页导航排入口（与「好友 / 帮助 / 设置」同排） |
| `#changelog-dot` | 入口上的小红点（**初始 `hidden`**；只在"有没看过的更新"时亮） |
| `#changelog-modal` | 弹层容器，**必须是 `.modal-overlay`**（浮层互斥按类名取全量元素，见 `closeOverlaysExcept`） |
| `#changelog-close` | 关闭 |
| `#changelog-list` | 列表容器 |
| `.changelog-entry` / `.changelog-date` / `.changelog-items` | 一条更新（时间 + 若干条文案） |

前端渲染纪律：**`textContent`**（不把服务端文本塞 `innerHTML`）、**时间原样渲染**
（不在前端重算格式，与私聊的 `stamp` 同一原则）、**文案一个字都不许写死在 `game.js` 里**
（有守卫测试钉这条）。

## 4. 文案规矩（本文件最重要的部分）

1. 玩家视角、以动词开头：**「修复了…」「改了…」「新增了…」「优化了…」「调整了…」**；
2. **一条一句话，≤ 40 字**；
3. **不许出现技术词**：文件名（`game.js`/`server.py`）、下划线或驼峰标识符、反引号、
   半角括号、`API`/`SQL`/`socket`/`HTTP`/`JSON`/`token` 这类缩写；
4. **不许出现账号参数**（等级 / 段位分数 / 解锁 / 特权 的具体数字或开关名）——
   与本仓库「提交说明只写改了什么、不写账号参数」同口径。

以上 1~3 由 `tests/test_changelog.py` 逐条守卫（它还会钉"时间格式 / 唯一 / 严格倒序 /
条目数 1~5 / `view()` 返回拷贝 / 前端没抄文案"）。

## 5. 约定：**每批更新都要在这里最上面加一条**

这是本文件唯一的用途，也是唯一容易漏的一步。做法（收尾时顺手做）：

```python
{
    'date': '2026-09-19 18:40',        # 用本机时间，格式 YYYY-MM-DD HH:MM
    'items': ['修复了：…', '新增了：…'],   # 1~5 条，口语
},
```

⚠️ 漏加**不会报错**，只是玩家看不到这次改了什么。
（我特意**没有**把"最新公告时间 ≥ 最近一次提交时间"做成测试：那会让 pytest 依赖 git 与仓库完整性，
本项目跑测试的环境不保证有 git。这条靠约定 + 收尾自查。）

## 6. 前端行为（`static/game.js` 末尾「更新公告」一节）

- `fetchChangelog()`：拉一次并缓存（内存），**失败静默**（公告是锦上添花，绝不许挡住任何东西）；
- `openChangelog()`：互斥 → 显示 → 渲染 → 把 `latest` 写进
  `localStorage['battleship_seen_changelog']`（打开过就算看过，顺手清红点）；
- `maybeAnnounceChangelog()`：`initChangelogUI()` 里延后 900ms 调一次，**四个条件全满足才自动弹**：
  ① 已登录（`window.__USERNAME`）；② `localStorage['battleship_active_game']` 为空（不在局里）；
  ③ `seen !== latest`；④ 当前没有别的 `.modal-overlay:not(.hidden)` 开着（不抢屏，红点留着）；
- 红点：`updateChangelogDot(hasNew)`。

## 7. 已知取舍

1. **只对登录用户自动弹**：游客在登录页被弹窗打断体验更差；游客仍可从入口主动看（接口公开）。
2. **"看过"记在浏览器本地**：换浏览器 / 清缓存会再弹一次。不引入服务端已读表（为一条公告建表不划算）。
3. **入口会被合作者挪位置**：他正在做 UI 重构（`docs/UI_REBUILD_PROPOSAL.md`）。
   挪位置只动 `index.html` 的那个按钮即可 —— 取数与渲染的唯一入口是 `openChangelog()`，
   它已经挂在 `window` 上；**不要**在新 UI 里另写一套 fetch + 渲染。
4. 公告条数不清理（现在 7 条，`limit` 默认 10、上限 20）。等超过 20 条再谈"要不要折叠更早的"。

### 8.1 顺手抓到的一条真缺陷（已修）

回归工具跑出来：**先开「更新公告」再点「帮助」→ 两个浮层同时开着、帮助压住公告**
（两者 z-index 都是 10000，帮助在 DOM 里靠后；公告中心点上的最顶层元素是 `help-content`），
公告读不了也点不动。

根因不在公告这边：`static/game.js` 里 `helpBtn` 的 click handler 是**全项目唯一没调
`closeOverlaysExcept` 的浮层入口**（设置 / 名片 / 战绩 / 好友 / 公告那几处都调了）。
→ 补一行即可（`#help-modal` 本身就是 `.modal-overlay`，按类名取的全量互斥自动覆盖它，
**不需要**往任何清单里加 id）。修完复跑 **56/56**。

> ⚠️ 这条值得记：新加一个浮层时，最容易漏的**不是**新浮层自己，而是**旁边那些老入口**
> ——它们当年各自手抄了一份"要关谁"的清单。本仓库已经把这个形状收成"按类名取全量元素"
> （另一个会话的 `tests/test_screen_overlay_registry.py` 就是为它写的），
> 这条缺陷说明**当时漏掉了 `help-btn` 这一个调用点**。
