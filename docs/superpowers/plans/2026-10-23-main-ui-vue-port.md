# 将原 main 前端迁为 Vue 实现

执行方式：DSH 使用 executing-plans 逐项实现；Codex 独立审查和验收。用户已确认本设计并要求开始，不重复征询同一方向。

目标：以原 main 的页面结构、布局、视觉和交互为前端主体，用 fork 的新框架实现，而不是在 fork 现有界面上继续换皮；只融入已认可的三项改进。

架构：后端 FastAPI、Socket.IO、SQLAlchemy/Alembic 不回退；前端保留 Vue 3、TypeScript、Pinia、Vite和当前服务端协议。原 main 的 DOM 结构按职责迁为 Vue SFC，以 computed 和 store 绑定现有状态；原样式层次迁为可维护的组件/全局样式。原 game.js 只作交互参考，不进入产品运行时。

规范来源：本轮任务文件及用户明确纠正，优先于上一轮“仅改现有fork视觉”的任务。原 main 为固定提交 `d16f706e61acb02a4ca7197cd2a92400c92c568d`，参考目录 `D:\Codex workspace\main-ui-reference-d16f706`，baseline-manifest.json 给出来源及逐文件哈希。

1. 桌面左右双棋盘同时可见且都有实际状态，己方舰艇可直接选择，不再依赖小地图浮层。
2. 手机/横屏保留main的紧凑适配与真实可点的两海域入口；标签、标题、实际提交的board必须一致。
3. 长卡文、连锁、多目标/选船、护盾选择、区域选择不能遮住需要点的棋盘；检测裁切、层级和命中位置，而不只看整页scrollHeight。
4. 主题与背景同时存在时，原main的层次、卡面和文字仍清楚；根theme属性与Vue状态同源，切屏不丢设置。
