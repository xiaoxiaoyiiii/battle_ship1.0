# 阶段转换时点实现计划

> 按用户明确指定，由 Codex 独立按步骤实现，不桥接、不新开分支。

**目标：** 对手进入战斗、结束阶段前，有合法速阶三才询问；等待时服务端冻结对局操作。

**架构：** 复用旧 main 的 priority_request/priority_response/set_decline_priority 协议。服务层维护带令牌与截止时间的阶段请求，响应出牌复用 MagicService，正常连锁完成后重新校验并继续原阶段。Vue 弹窗与设置共用持久化偏好。

**技术：** Python asyncio、FastAPI/Socket.IO、Vue 3、TypeScript、Pinia。

**规格：** 本会话已确认的完整方案，旧 main @ d16f706 的 server.py/static/game.js 为行为参考。

## 约束

- 在 review/main-ui-vue-port 工作，不桥接，不改其它布局，不自动推送。
- 仅 enter_battle/enter_end；默认开启，旧 main 的 10 秒权威期限。
- 仅展示当前合法速阶三；弹窗选卡后复用已有目标选择。
- 等待时双方不能从其它入口写棋盘、出牌或推进阶段；保留聊天、只读查询与投降。
- AI 转阶段询问真人；真人转阶段 AI 自动放行。
- 测试、截图置仓外；完成后更新 5472。

## 重点边界

1. 双击、旧超时与响应并发：只执行一次；过期令牌拒绝。
2. 选目标不重置期限；无效响应可在原期限内重试。
3. 重连恢复双方等待状态且不泄露响应方手牌。
4. 连锁产生后置选择或棋盘重摆：义务完成才继续，状态已失效则取消续做。
5. AI 必须等待询问和连锁后再继续，不在后台穿透冻结。
