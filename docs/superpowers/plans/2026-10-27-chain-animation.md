# 连锁动画实施计划

> 执行方式：按 `executing-plans` 由Codex在当前会话独立实现；不桥接DSH。用户已审核概念v3并明确要求开始，本计划直接执行。

**目标：** 将通过审核的接链、金属链、大编号、Successful Chain及真实倒序结算接入双人对局，稍放慢飞入。

**架构：** 服务端每次新增连锁项后先保留0.8秒演出时间，再开放完整10秒响应窗口；超时或放弃转移窗口不再重复等待。客户端独立维护只用于展示的事件队列，真实规则仍由现有服务端负责；已有公开连锁与结算事件不增字段、不增加协议。独立Canvas叠层复用真实卡面，不增加页面盒模型尺寸。

**技术：** Vue 3、Pinia、TypeScript、Canvas 2D、FastAPI/asyncio；不增加依赖。

**规格：** 仓外 `battle-ship-chain-animation-proposal-20261027/concept-v3.html` 与用户本轮确认：飞入稍慢；先播约0.8秒，再弹响应面板并开始完整倒计时。

## 重点验证

1. 两端收到同样卡面、顺序与结算结果；被无效卡跳过效果，前端不推断规则。
2. 响应计时在入链演出之后开始；重复放弃不增加演出等待；延迟期间额外出牌不被接受。
3. 重复快照不重播，同名重复卡保持独立编号；快速连锁与前一连锁未播完时的新连锁不串台。
4. 重连、隐藏页面、换房与卸载清理旧展示；新选择面板不会被动画覆盖。
5. 手机/桌面不溢出、不挤动棋盘，减少动效不播飞入；只有真实双端验证后才声称双端可用。
