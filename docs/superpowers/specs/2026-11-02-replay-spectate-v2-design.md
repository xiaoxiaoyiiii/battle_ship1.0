# 回放与观战 v2 设计

## 已确认的意图

用户认可上一轮诊断提出的模块重构方向：回放、观战在底层重构后未充分适配，应系统更新，并覆盖现有词条玩法。独立执行，不桥接、不向其他人派活。

诊断证据：`D:/Codex workspace/battle-ship-replay-audit-20261102/REPORT.md`。该报告中的 5 份真实录像、记录器复现、服务结算和 Vue 页面证据是修复验收的起点。

用户于本轮明确确认：开启“公开手牌”或“点名亮舰”时，观众也能看到词条公开的牌名、舰位。

## 交付效果

1. 新录像按权威结果还原整局，攻击落在正确的受击棋盘；抽弃牌、复活、补舰、重摆、词条触发和公开效果在相应时点更新。
2. 回放、观战共用一个只读战斗舞台与演出展示层。双方棋盘在一个连续海域容器内，共用中线、状态与演出定位；不再各自套独立信息卡片。棋盘各自仍为 6×6，不改变坐标或游戏规则。
3. 连锁加入、无效化、结算卡面和已有牌效能连贯观看。回放支持暂停、逐步、1×/2×/4×、拖动和关键节点跳转；跳转不残留旧演出。
4. 观战在抽弃牌、舰船变化、复活、重摆、词条触发后及时更新；中途加入与重连通过权威快照恢复。
5. 本局词条文案和规则版本随录像冻结。以后轮换词条或修改卡牌规则，不会重新解释过去的实际结果。

## 边界与禁止项

- 保留卡牌规则、结算、匹配、排位、Ban 和词条选择机制。本任务只记录、投影与展示已确定的事实，不重算牌效、胜负或随机结果。
- “每日词条”按当前已落地的每周突变 v3 / 自定义词条适配，不在本任务新增日历轮换玩法。
- 不新增运行依赖，不复制整套 GameScreen，也不把观看页面接进玩家可操作状态。
- 回放继续使用现有 HTTP 入口与权限；观战继续使用独立观战房间、开放观战开关和聊天机制。普通隐藏船位、手牌、选牌草稿、ACK token 不进入观战包。
- 开启 E2 时双方牌名对观众可见；开启 E3 时词条已公开的舰位对观众可见。探测雷达等仅某玩家获得的私有情报不能因此自动公开。
- 观众不发送玩家 `chain_animation_complete`，不进入玩家动画完成等待集合。观看端慢、退出或断线不影响比赛推进。
- 保留旧录像；不批量迁移、删除或覆写用户存档。无法恢复的旧数据明确标示兼容边界。
- 业务代码执行前遵守 AGENTS.md 指定的 `review/main-ui-vue-port` 分支约定，保护其旧工作树已有未提交内容。当前 detached 工作树只落设计文档，不强制移动分支。
- 本轮尚未获得针对本次重构的远端推送、合并或线上部署新授权；准备与实现先在本地验证。既有 5472 / 数据库在验证完成前保持。

## 技术方案（以下为实施者建议）

### 一、单一权威投影，明确可见范围

新增纯领域模块 `domain/viewing.py`，从当前 Room 产生统一观看帧：

- `context`：阶段、大回合、当前行动方、剩余额度、场地、胜负/待重摆状态。
- `rules`：本局模式、Ban 结果、实际词条 ID 与完整文案、冻结的规则版本、起始舰数和实际骰子结果。无词条使用空列表。
- `players`：稳定 p1/p2、名字、舰数、手牌数量；内容是否提供由可见范围决定。
- `boards`：按**棋盘所有者**编号的两盘状态。攻击事实与可见标记分离，迷雾空炮事实不会被误画成持久标记；整盘替换、局部清除均反映在完整结果里。
- `public_effects`：冻结、神威孔洞、公开亮舰、场地、词条当前状态等。
- `chain`：实际栈、顺序和结算结果。

提供两种明确投影：赛后授权回放可持有双方完整局面；实时观战仅白名单公开局面。两者共用坐标和字段语义，不能把完整帧删几个字段后当作公开帧。

词条规则文本从 `room.mutation_entries` 冻结，不在读取旧录像时查询当前 calendar。抽牌数、额度、支付次数、骰子结果、暴雨是否激活、E3 已公开点位均采用服务端实际状态。

### 二、新录像 v2：状态与演出分开

新包保留现有 match 存档入口，版本升级为 2。内容包括元信息、初始权威帧、有序事件、检查点和截断提示。

- 事件使用严格递增 `seq`；日志步骤使用 `step`，同一 step 允许多个有序状态和演出事件，消除“同一步覆盖前一批”的歧义。
- 状态变更为指定板块的**整体替换**，空列表明确表示清空；不再用只新增攻击格子的增量冒充完整状态。
- 每 32 个状态事件保存一份完整检查点，跳转从最近检查点恢复。前端只应用状态，不执行卡牌或随机逻辑。
- 连锁入栈、结算卡面、牌效前导/命中/尾声作为独立演出描述记录，保留真实顺序、结果和公开/私有目标范围。
- 录制点落在语义动作完成及牌效落点处：出牌与付费、结算、交互确认、布船/补舰/重摆完成、阶段切换、词条亮舰和终局。无日志的状态变化也必须录到。
- 现有 `note_*` 入口逐步转接 v2；不依赖用户可见的中文日志来反推游戏状态。
- 继续执行 2000 步、512 KiB 的现有限制。空间裁剪只丢完整后缀，保证保留下来的事件、检查点和最后状态一致；显式显示截断，不把未来状态当作更早帧补入。

### 三、观战权威帧与演出流

新增 `spectate_frame` 出站事件：`{version:2, room_id, seq, frame, cues}`。初始 `spectate_sync` 增加同形的 `viewing_frame`，中途加入拿到完整基线。

服务层新增 ViewingService，统一编排录像记录和公开观战发布，领域层不导入网络或数据库。接入现有房间串行写锁的最外层提交边界；对未经过该边界的定时器/AI/牌效交互续做，显式接入同一提交入口。逐项审计，不能只修真人 Socket 入口。

公开帧在实际状态变化后发布；嵌套动作避免重复提交。通过稳定 seq 丢弃重复和迟到帧，重连重新获取基线。战斗状态只认 v2 权威帧，名单、聊天、观众数继续消费原有事件。

演出描述经过明确净化：公开选区保留，私有落点去除或降为无定位反馈，绝不直转玩家 room_sync 或私发效果包。

### 四、一个只读舞台，两种数据适配

新增 `screens/viewing/`：类型与投影适配、BattleStage、规则摘要、观看动画层和播放器。回放与观战屏幕只负责编排各自的数据来源与控件。

BattleStage 复用 `game/BoardPanel.vue`、`BoardCellIcon.vue`、`cellPresentation.ts` 的展示资源；所有棋格 `interactive=false`。双方棋盘放在连续海域中，顶部对齐玩家/舰数，下部显示授权范围内的手牌或数量。

外观沿用实战当前主题变量、中文字体和舰船/炮击图形；不新做卡面或背景素材。桌面和窄屏均以双方并列的同一舞台为主；日志和聊天可收起，播放条保留在可操作区域。实施裁定：上下相邻的竖屏双盘在 320×568 实测会把控制挤出视口，改为统一海域内并列，并仅对只读棋格覆盖全局触控最小尺寸。五种目标尺寸已验证无横向溢出、控制未出屏。

复用现有 ChainTimeline、chainAnimationCanvas、CardEffectTimeline 和牌效绘制，不复用其绑定玩家状态/ACK 的控制部分。观看端维护自己的时钟、队列、音效和取消生命周期。

### 五、播放调度与实时观看

- 权威状态与画面状态分离：提前收到的实际结果不在动画命中前误画，命中时切换到已记录的结果；展示时间不参与真实结算。
- 暂停冻结观看时钟；倍速缩放同一时钟，不能只缩短日志切换间隔。
- 拖动/跳步/换局/退出立即取消旧演出与声音，恢复目标状态；不连播跳过区间，也不重复执行实际动作。
- 观战队列有界；积压时跳过过期装饰演出并恢复最新权威帧，不长期落后于实战。
- 减少动态效果设置跳过装饰运动，仍保留卡名、连锁顺序、结果和关键状态反馈。

### 六、旧录像兼容

后端读接口接受 v1 与 v2，不能升级版本常量后把所有 v1 拒绝为 409。前端显式适配两个版本。

v1 修复攻击方到受击棋盘映射和步骤上下文丢失；可依据明确记录恢复的状态继续显示。缺失的删除、被覆盖的攻击、从未记录的演出不能伪造。页面简短提示“旧版录像，部分状态或演出可能缺失”。不尝试从中文日志或当前词条表猜补历史。
