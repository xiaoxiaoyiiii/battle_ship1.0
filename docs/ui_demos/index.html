给「战舰棋」做了 16 版静态示意稿，分七批。前两批"重画现有界面"，第三批是产品级重设计，第四批按反馈精修（第四批就是当前候选：以 C 为底、双盘放大、实体手牌两级预览）。

这些是静态示意稿，不是可运行版本。前两批每版只画首页与对局屏两块（其余 8 个屏：大厅、排行榜、名片、好友、排位、设置、结算、布阵 沿用同一套语言，选完方向再一起做）。 所有文案、卡名、段位名、数据都取自真实实现（magic_card.json / ranks.py / 现有 DOM 的 id 与 label），所以观感即真实密度。 几何都是量过的：每条竖向预算按 390×844 / 1280×720 / 1440×900 实测收紧，无遮挡、无溢出（见文末「怎么复跑」）。

第一批 · A–D

A

战术指挥台

暗色作战终端：信息密集、发丝线、等宽数字。改动主要在信息架构而非配色。

  • 对局屏改成固定三栏（日志轨 / 战场 / 手牌轨），浮窗不再压在棋盘上。

  • 连锁从浮层变成战场上方的一条常驻条（现状只有 10 秒弹窗，错过就看不见）。

D

口袋舰队（移动端优先）

手机 App 范式：底部标签栏 + 底部抽屉 + 横向滑动手牌，单格 48px。

F

极简纸白

编辑式排版：近单色、无阴影无圆角，只用发丝线与字重组织层级。

第三批 · I–L（产品级重设计：不受现有布局约束）

这一批不再"重画现有界面"，而是重新设计**信息架构**，并且每一版都用同一个响应式页面在 1440×900 与 390×844 各出一套图 —— 手机上怎么收、桌面上怎么展，是同一个文件、同一套组件，不是桌面版加手机版两张皮。 每版都标了参考的成熟产品手法。

I

同一片海

把两块互不相干的棋盘合成一片 6×12 的海图，中间一条「前线」。窄屏竖着折叠、宽屏横着展开。
  • 核心改动：现在"你的棋盘 / 对手的棋盘"是两个互不相干的对象；这一版把它们当作同一片海的两片海域，你的攻击与对手的攻击都发生在一张图上。
  • 两端打通：窄屏两片海域上下长卷（前线是横线），宽屏左右双页（前线变书脊）—— 同一个对象两种折法。
  • 状态栏放在中轴上（窄屏顶栏放不下就把回合/阶段挪到前线那条），首页的"我的舰队"小图与对局里的海图是同一个东西。
打开示意稿 → 手机图 桌面图 代价 高
J

工作台

左轨道 + 画布 + 右检查器；选中即详情。手机把检查器收成上拉面板、轨道收成底部标签栏。
  • 魔法卡不再是"一排卡面"，而是检查器里的一张列表：点一行，上面就展开它的全文与"确认使用"。
  • 战报是画布里的一条时间线，不是浮窗；棋盘是画布上的一块面板，规格与状态写在面板头上。
  • 同一套三区在手机上变成"画布 + 上拉面板 + 底部标签"，桌面变成"三栏并排"—— 这是这一批里两端差异最自然的一版。

K

组件主页 · 焦点对局

主页是一屏可扫读的组件；对局是焦点模式：90% 是棋盘，其余全收进一个「更多」。
  • 组件：快速开战 / 段位环 / 赛季进度 / 每日任务 / 卡牌图鉴 / 最近对局 / 在线好友 / 本周最佳 / 成就 / 排行快照 —— 同一组组件按列数自适应。
  • 对局顶栏只剩回合与阶段，手牌是底部浮动 dock，日志与统计收进「更多」（桌面右侧抽屉 / 手机上拉面板）。
  • 棋盘被放大到 430px（现状 300–340），页面装饰几乎为零 —— 这是"内容优先、壳最轻"的路子。

L

航线 · 赛季通行证

把段位从"一个数字"变成一条可走的航线，进度本身就是导航；对局是竖屏街机台。
  • 航线节点 = 段位节点，每个节点写清"到这里解锁什么"，你的船停在当前节点上；玩一局 = 往前推一程。
  • 模式选择从"5 个并排按钮"收成一个主按钮 + 一行段控件（出海 → 休闲/排位/人机）。
  • 赛季通行证双轨（免费 / 高级）；对局屏在桌面也保持竖屏，两侧填战报与手牌。
  • ⚠️ 这一版含新功能（航线可视化 + 赛季通行证涉及商业化），不只是 UI —— 选它要先做产品决策。

竞技场最小改动

手牌与预览行为（规范稿）

第五批 · R（自查返工）

交付第四批后自查发现一处硬伤：那三版的"卡"是 62px 横条插图 + emoji 占位， 本质是深色小方块，不是真实卡牌 —— 你连着强调"真实手牌"还提到要配卡面，这一处不达标。 R 版把卡按真实 TCG 结构重做，并把我在 M 里退化掉的「连锁叠牌」恢复。

R

真实卡牌版

卡尺寸 150×210（比例同真实 TCG 63×88mm）· 满幅插画占 53% · 名牌 + 速阶宝石 + 独立说明框 · 双层卡框 + 实体厚度 · 三态同屏对比
  • 卡面结构：满幅插画（104px / 53%）→ 名牌 + 速阶宝石 → 独立说明框 → 类型条；卡框是双层（外层暗金描边 + 内层亮线 + 顶部高光 + 底部厚度影子）。
  • 插画不再用 emoji：每张牌一个手写内联 SVG 意象（雷达同心圆 / 火焰弧 / 断链叉 / 桃形簇 / 契约五芒）。生产环境这一块就是 docs/magic_card_art_prompts.md 生成的那张竖版插画。
  • 连锁恢复成叠牌：右栏是三张真卡叠起来（每张只露 34px 切片，只有最上面那张全露），并标出自下而上的响应顺序 —— 连锁本来就是"一叠卡"，M 里退化成提示条是倒退。
  • 三态同屏：常态 / 一级预览（−30px · 1.05）/ 二级预览（−56px · 1.09 + 右侧出介绍）在同一排里直接对比，不再另开说明页。
  • 仍待定：这些数值（扇形角度、重叠、抬起量）目前是我按"手感"定的，正在做市面卡牌游戏的调研，回来后用实测/公开数据替换。

第六批 · S（移动端调优）

按一手来源（Apple HIG / W3C / androidx 的 Material 3 令牌 / Balatro 反编译源码）调优手机布局。 三条查实的问题：① index.html:5 缺 viewport-fit=cover 而 style.css:3665/3978 用了 env(safe-area-inset-bottom) → iOS 上留白恒为 0；② style.css:3831 紧凑档手牌 64×92，中文效果文字读不了； ③ adaptive_layout.js:135 在 390×844 上判为"两块 364px 棋盘上下堆"，而实测可用高只有 763px（844−47−34）。

S

移动端调优 · 一屏一块 · 真卡抽屉

手机改走 tabs（一次一块棋盘，格宽反而更大）· 小卡只负责"认出是哪张"、抽屉里给 200×280 可读大卡面 · 操作条进拇指区 · 按实测安全区算预算
  • 格宽：390×844 下 55px、320×568 下 41px、横屏 664×336 下 41px —— 三档都高于项目 MIN_CELL=40，390 那档也高于 HIG 44pt。
  • 竖向预算按实测可用高 763px 算：状态栏 47 + 顶栏 87 + 回合条 42 + 棋盘 366 + 手牌 150 + 操作 48 + 安全区 34 = 774（含留白），战报改走抽屉。
  • 抽屉令牌用 Material 3 实现值：遮罩 32% 黑、顶部圆角 28dp、把手 32×4dp；操作条 48px（Material 推荐 48dp）、间距 12px（Apple 建议）。
  • 两条被独立印证的决定：手机一屏一块（两块 632 + 手牌 110 + 顶栏 44 + 操作 48 = 834 > 763）；需要选区域目标的卡要有确认步（Hearthstone 无确认但选的是单点，Balatro 对"先选再确认"才有先例）。
  • 仍为推测：各游戏客户端手牌像素尺寸、拇指区百分比、320 宽机型安全区为 0、"点开放大"对 CJK 小字的实际收益。

第七批 · T/U（C 上的新状态与新主次）

T

目标选择态

点开 神威！之后到底发生什么：落点高亮 → 已选待确认 → 越界无效 三个状态。
  • 依据一手调研：Hearthstone 的"松手即生效"是为单点目标设计的；神威！是 3×3 区域、轰炸是整行整列， 误触代价大得多，而两家都不能撤销 → 按 Balatro 的先例先选、再确认。
