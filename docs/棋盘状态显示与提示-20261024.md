# 棋盘状态显示与提示

## 本轮实现

- 炮击落空：灰蓝格、空心圆与水面涟漪。
- 舰船命中／沉没：红格白叉，船形弱化在叉号下方。
- 护盾挡炮：金色破盾，与红叉区分；不表示当前仍有护盾。
- 护盾保护：青色完整盾与船形。
- 己方陷阱：紫色警戒三角；与护盾并存时保留角标。
- 合法待选格：绿色虚线框；悬停区域叠加半透明范围；点击固定落点，单格／多舰选择保留实框及勾号，保留原命中与护盾图案。

只给护盾挡炮、护盾保护、陷阱、当前可选目标增加悬停／键盘聚焦提示。普通格、落空、命中不弹提示。冻结、轰炸等使用当前卡牌名及选择要求；非法棋盘不亮待选框。

提示通过根节点浮层展示，按视口夹紧，不拦截格子点击，离开、滚动、切换棋盘和按 Escape 会关闭。

## 数据与边界

- 按实际规则，舰船陷阱来自「守株待兔」；「亡羊补牢」是取弃牌，不将其误标为陷阱。
- `ships` 子项新增可选布尔 `trap`，仅在本人实时舰船更新及重连快照中提供。旧载荷缺字段视为没有陷阱。没有新增顶层协议或数据库表。
- 陷阱广播只保留公开的设置者，不广播位置；本人通过自己的舰船快照得知位置。对手不显示陷阱。
- 完整护盾仅本人可见。`opponent_shielded_ships` 保留兼容字段但服务端恒发空数组，前端也不绘制其中的位置；挡炮公开事件只包含实际被击中的格子。
- 真正命中优先于旧挡炮记录；重新获得护盾优先显示当前完整护盾。
- 既有格子测试标识和 `data-cell` 兼容字段保留，新增 `data-visual-state` 表示本轮视觉状态。
- 不改攻击、护盾消耗、陷阱触发和魔法选区的服务端结算规则。

## 后续修正（2026-10-24）

- 挡炮事件当帧消费本人护盾，不再等下一回合完整同步；命中记录与重新加盾的优先级不变。
- 新房间首帧由状态层清理破盾标记、旧日志及未完成提示，避免依赖尚未挂载的对局页面；同局刷新与卡牌重布保留历史。
- 区域与行列卡悬停预览、点击定位、确认提交相互独立；移出恢复已定位区域，悬停不会使未选目标可确认。
- 「桃园结义」按旧 main 的自己→对方两步选牌，明确双方归属，可重新选择；「明智埋葬」显示卡牌效果及来源。服务端拒绝时保留窗口与选择，不提前声称分牌成功。
- `state-regression.mjs` 覆盖挡炮当帧清盾、新房间清理、同局快照与重布不误清。`check-board.mjs` 追加预览九格与不提交、桃园两步与禁重复、埋葬来源下标、拒绝回执保留及小屏确认按钮可达检查。

## 连锁窗口动效

响应窗口与遮罩统一淡入 160 毫秒、淡出 120 毫秒；退出过程中不拦截鼠标。收起和重开沿用原待响应状态与开启时间，不重置倒计时；减少动态效果偏好下立即切换。仅包装现有窗口，没有改动连锁结算规则。

仓外 `check-chain-fade.mjs` 在生产构建下记录实际透明度变化与过渡事件，检查收起重开后的剩余时间、淡入淡出时长及减少动态效果模式。
