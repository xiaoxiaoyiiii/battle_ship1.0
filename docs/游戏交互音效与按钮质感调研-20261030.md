# 游戏交互音效与按钮质感调研

调研日期：2026-10-30。目标：增加按钮和对局行为的听觉反馈，改善按钮的实体触感，继续使用战舰棋现有的深海、青蓝与金紫卡牌美术。本文件只记录研究与适配建议，不代表已经实现或经过真人试听。

## 1. 可以直接用于本轮实现的结论

1. 普通按钮采用统一、克制的短促点击声；确认、返回、切换、拒绝和实际完成的对局行为用不同语义音色。统一入口覆盖常规按钮，明确的行为入口覆盖通用声音，一次激活只选一个即时交互音。Mindustry 的全局按钮声和 OpenRA 的按钮封装证明了集中接入的可行性；细分音色属于本项目方案。[M1][O1]
2. 布船成功、目标选定、完成部署等声音跟随实际接受的操作或明确完成事件。不能在鼠标经过格子、框选预览、普通日志或者网络状态重放时发成功声。OpenRA 在放置失败的分支中同时发声音和文字；本项目既有 Toast 规则也区分“要求操作”与“真正完成”。[O3][L2]
3. 不给每个 hover 默认配声。让 hover 负责边缘高光，让 pressed 负责压下，让真正激活负责声音；高频选格另做节流。这个取舍是本项目设计判断，依据是保持关键事件声音可区分，以及避免同时声源过多。[A1][A2]
4. 按钮质感由深色底座、薄顶面高光、可见边线和按下时的深度变化组成。保留原有颜色职责：深蓝背景、蓝灰边线、紫色主操作、青色己方、金色连锁与荣誉。不要把所有按钮都变成金色装饰。[L1] OpenRA 的九宫格面板与 1 像素按压深度、Godot 的独立状态样式是具体参照。[O1][O4][O5][G1][G3]
5. 音效要服从现有静音和音量设置；通知、错误、回合等信息仍保留可读的文字或视觉状态。关键结果不能只靠声音传达。[A2][A3][A4]

## 3. Mindustry：集中接入按钮声，样式分别描述状态

- `UI.java:146` 把全局 `ClickListener.clicked` 接到 `Sounds.uiButton.play()`。这意味着普通 UI 点击反馈可以统一覆盖，而不是每个页面复制播放代码。[M1]
- `Styles.java:133-141` 的默认文本按钮分别设置 normal、over、down、disabled 的底图与文字颜色；`220-229` 的 toggle 按钮还单独设置 checked。按钮是否选中和当前是否按下是两种状态，不能只靠一个 hover 类代替。[M2]
- `SettingsMenuDialog.java:367-371` 分开提供音乐、效果、环境声的百分比滑块。这是可核实的分组，不应描述成它已有独立的“UI 声音滑块”。[M3]
- `InputHandler.java:711-714` 在实际旋转建筑后发旋转效果、播放 `blockRotate`，并对音高做小幅随机。可借鉴“声音跟随行为完成”的位置；没有证据表明所有按钮都应随机变调。[M4]

适配：常规菜单/弹层按钮可统一覆盖；持久切换状态有独立选中外观；布船旋转可用一次短机械拨片声。上述代码没有证明“返回”和“确认”默认使用不同按钮声，因此本项目对这两类声音的区分应明确写成自己的声音语言设计。

## 4. OpenRA：区分播放入口、数据配置与真正生效的状态

### 4.1 普通点击、快捷键和拒绝

`ButtonWidget.cs:44-45` 提供 `ClickSound` 与 `ClickDisabledSound`。`147-161` 处理快捷键，`190-203` 处理鼠标按下，两条路径都选择正常或禁用的声音。鼠标的业务回调则在 `181-187` 的有效松开时触发，所以这里的点击声表示“按压触感”，不能等同“业务成功”。`DisableKeyRepeat`、`DisableKeySound` 也是显式选项。[O1]

必须注意实际配置：Red Alert 的 `notifications.yaml:138-140` 将正常点击映射到 `ramenu1`，并允许 Overlap，而禁用点击声留空。源码支持拒绝音，不等于这个 mod 默认按禁用按钮会响。Checkbox 继承 ButtonWidget，可复用按钮输入路径；这同样不能证明它默认有独立开/关音色。[O2][O6]

适配：常规按钮正常激活一次有轻扣声；原生 disabled 按钮保持禁用语义，不为发声而改成可点击。对仍可操作、但被规则明确拒绝的动作播放独立低短音，并保留原因文字。键盘 Enter/Space 与触摸点击覆盖同一语义。

### 4.2 放置失败、取消与目标提示

`PlaceBuildingOrderGenerator.cs:185-202` 在建筑不能放置的分支中调用声音通知并追加文字通知，随后退出；`131-148` 区分取消与可接受的放置命令。[O3] Red Alert 的数据定义还单列 `Cancelled`、`BuildingCannotPlaceAudio`、`SelectTarget`，表明通知语义与音频资源之间有明确映射。[O2]

适配：选船、旋转、成功落船、取消选择、非法位置应有不同程度的反馈。不能用“任意棋盘点击”统一代替这些结果。声音的左右声像可以是装饰，但不能成为判断海域或位置的唯一方式。[A3][A4]

### 4.3 通知如何限制叠声

`SoundInfo.cs:66-94` 的 SoundPool 支持 `DoNotPlay`、`Interrupt`、`Overlap`，默认是 DoNotPlay；素材池随机取一个片段，并在本轮用完前从候选池移除，避免无约束连续重复同一片段。[O7]

`Sound.cs:419-438` 针对正在播放的同名通知决定重叠、打断或放弃。键是实际资源名称，不能把它夸大为完整的“业务事件幂等系统”；业务级重复消息仍需上层自己去重。`415-416` 同时乘入总效果音量、调用修正值与素材池音量。`320-352` 把效果、音乐、视频音量分开。[O8]

Red Alert 的实际取舍也不是“一律不叠”：金钱滴答音允许重叠且单独减小到 `0.33`；聊天、加入、离开与大厅选项变更采用 Interrupt；普通菜单点击采用 Overlap。[O2] 因此战舰棋应按声音类别选择并发策略，不能照搬一个全局冷却。

### 4.4 按钮为什么有“压下去”的感觉

- `ButtonDepth: 1` 是公共指标。按钮内容与文字在 depressed 时一起偏移，这为按压反馈提供了明确的空间变化。[O1][O5]
- `WidgetUtils.cs:33-42` 根据 disabled、focused、pressed、hover 选择状态；`160-165` 定义九块面板区域，按钮可变宽而保留边角。[O4]
- Red Alert 的 `chrome.yaml:420-447` 分别提供 normal、hover、pressed、disabled、highlighted 的面板区域。注释明确 hover 比正常状态亮约 5%；其做法是小幅调整材质状态，而非 hover 后换成完全不同的设计。[O9]

适配到 Web 可以用 CSS 渐变、边线和内外阴影表达这些层次，无需复制 OpenRA 的贴图、字体或九宫格图集。

## 5. Godot 官方演示和文档给出的补充

- `gui/theming_override/test.tscn:5-46` 分别定义半透明焦点层、hover、normal、pressed 的 StyleBoxFlat；normal、hover、pressed 的灰面亮度不同，各自有边线。[G1]
- `2d/platformer/gui/theme.tres:5-79` 使用深蓝灰按钮底色，分别指定 disabled、focus、hover、normal、pressed。焦点边线偏蓝，pressed 的文字和图标也发生变化；不能只给背景换颜色，忽略文字可见度。[G2]
- 官方 Button 文档明确 focus 样式覆盖在基础 StyleBox 上，推荐透明描边或下划线，并说明去掉焦点视觉会损害键盘/手柄导航。[G3] 因此 focus 应是独立外圈，与 pressed/selected 共存。
- 官方 AudioStreamPlayer 文档将其定位为非空间 UI/菜单声音；`max_polyphony` 是同时播放上限，超出时切掉较早声音。它证明“有意识限制并发”是明确能力，不代表应把战舰棋 UI 也设成 1 路。[G4]
- `audio/audio_effects/audio_effects.gd:4-36` 使用按钮 pressed/toggled 信号驱动对应音频；`39-56` 演示按开关启停音频总线效果。它是交互演示，不是完整菜单声管理器，不能据此声称已解决事件重复或音量偏好存储。[G5]

## 6. 战舰棋声音语言与事件矩阵

下表是基于以上证据形成的本项目建议，不是从游戏源码抄来的音频参数。时长与节流值是第一版试听起点，需由实际听感再调整。可以继续用项目自己的合成音与现有合法资源。

| 行为 | 声音建议 | 正确触发点 | 重复策略起点 |
| --- | --- | --- | --- |
| 普通按钮 | 35–65ms，低音量机械轻扣 | 一次有效 click/键盘激活 | 同语义约 45ms；无 hover 声 |
| 确认、创建、准备 | 60–110ms，短促上行，带一点金属弹性 | 本地确认动作；服务结果另用成功/失败通知 | 覆盖该次通用 click |
| 返回、关闭、取消 | 45–90ms，柔和低落音 | 确实返回、关闭或取消成功时 | 覆盖该次通用 click |
| 开关、页签切换 | 35–70ms，轻拨片；开关用不同结尾 | 值确实变化，不对重复设置同值发声 | 同语义约 65ms |
| 选船、选卡、选目标 | 35–80ms，轻微玻璃/机械组合 | 选中项或目标集合确实变化 | 约 70–100ms；拖动预览静默 |
| 旋转舰船 | 40–80ms，机械卡扣 | 方向确实变化 | 约 80ms |
| 舰船放置 | 80–130ms，轻实体落点 | 布局接受了这艘船 | 每艘一个；批量随机布阵一次汇总 |
| 非法位置、规则拒绝 | 80–130ms，低短双击，无尖锐蜂鸣 | 已知拒绝结果，并显示原因 | 约 180–250ms |
| 提交、确认选区、部署完成 | 100–180ms，短上行完成音 | 明确完成标记或成功响应 | 同一结果一次；避免 Toast 再补一次 |
| 轮到自己、需要响应 | 140–240ms，清楚但克制的双音 | 真正转为己方可行动/待响应 | 同一阶段标识一次；重连不补播历史 |
| 通知/奖励/任务完成 | 120–220ms，轻亮双音；荣誉可带少量金属泛音 | 新通知或真正领取成功 | 同类约 400–600ms；同一业务事件一次 |

同一次输入的语义音覆盖普通点击音，避免“点击声 + 切换声 + 成功 Toast 声”同时叠加。异步操作的按压触感与最终结果可以分开，但不要在请求发出时先播放“领取成功”一类完成音。重要回合/拒绝/通知声应与连续点格的小音色有所区别；这对应 GAG 对关键事件可区分性的要求。[A1]

建议用简短语义键管理播放，例如 `ui-click`、`ui-confirm`、`ui-back`、`ui-toggle`、`ui-reject`、`ship-select`、`ship-rotate`、`ship-place`、`target-select`、`turn-ready`。名称是本项目建议，实际实现应优先沿用已有音效模块的命名。

## 7. 与现有美术一致的按钮材质规范

本地视觉方案已明确：背景 `#0b1120`、面板 `#111c2e`、边线 `#26364d`、主操作 `#a990f5`、己方 `#61c7d8`、荣誉/连锁 `#debd79`。[L1] 这一配色定义了本轮的边界，不需要从外部游戏迁入新的金属材质图片。

| 状态 | 建议表现 | 依据与边界 |
| --- | --- | --- |
| normal | 深蓝顶面、1px 蓝灰边、上沿窄高光、底部短深色阴影 | 借鉴 OpenRA 的面板与深度；渐变本身为本项目设计 |
| hover | 顶面轻微提亮、边线略亮，保留原背景色相 | OpenRA 小幅提亮的状态设计；不要全屏泛光或闪烁 |
| pressed | 顶面略暗、外部底座阴影缩短、内阴影增加；内容向下约 1px | OpenRA ButtonDepth 与内容偏移；保持点击区域尺寸 |
| focus-visible | 2px 清晰外圈，留约 2px 间隔，压下/选中时仍可辨认 | Godot focus 覆盖基础层的方式；数值是本项目建议 |
| selected/checked | 保留选中边线和持续的低亮填色；与暂时 hover 区分 | Mindustry 的 checked 独立状态 |
| disabled | 保留形状与文字可读度，弱化高光、阴影和强调色；不触发压下动画 | 独立 disabled 状态；不要全局低透明度导致读不清 |
| 主操作 | 沿用紫色强调，青蓝作为边缘反光 | 保留本地颜色职责 |
| 荣誉/稀有/连锁 | 金色仅用于语义相关的按钮和局部饰边 | 不与卡牌的金紫视觉争夺主次 |

若当前已有圆角、尺寸与状态类，只增强它们的高光/深度，不通过改变整个布局或引入粗铆钉/大磨砂纹理制造“质感”。减少动效模式保留静态亮度和边线反馈，去掉位移/过渡；这一条是本项目适配建议。

## 8. 音量、无障碍与验收

GAG 要求关键事件音色可区分、不同音频类别可调整，且必要信息不能只由声音传达；它同时指出过多并发声源会影响辨别和舒适度。[A1][A2][A3][A4] 本轮可以落实为以下可观察行为：

- 静音后仍能凭按钮状态、部署结果、错误文字与回合提示完成一局；声音不替代现有日志、Toast 或海域提示。
- 现有音效开关和音量滑块控制新增声音；音量为零时新增声音也静默。增加独立 UI/战斗分组可作为后续选择，不必为了本轮扩声改造整个设置页。
- 普通鼠标、触摸、Enter/Space 都是一次激活；同一按钮的图标/文字子节点不重复发声；语义操作覆盖普通 click。
- 关闭菜单、切页、确认、开关改变、选船、旋转、放置、非法放置、选格、取消、完成选区至少各实际走一遍。等待网络或 disabled 期间没有成功提示音。
- 连续快速点格、反复切页签、重连与重复状态推送不会形成持续刺耳叠声；通知去重按业务标识，不按显示文案猜测。
- 全局按钮材质不能覆盖卡牌自己的美术边框；pressed 与 focus-visible 同时存在时仍能看到焦点，disabled 不残留 hover 高光。

这里是实现后的验收建议，本次调研没有执行上述产品测试。

## 9. 资产与许可边界

本次只借鉴事件语义、状态组织、播放并发和材质层次。Mindustry 与 OpenRA 的官方源码分别带 GPL 许可信息；Godot 演示的根许可为 MIT，但项目中的个别资源还有各自的许可文件。[P1][P2][P3] 本轮没有复制它们的实现代码或下载音频/贴图。后续若选择外部素材，应逐文件确认授权与署名要求；当前建议优先使用项目已有合法音色或自己合成的短音。
