# 连锁动画实现与验收

本次将用户审核通过的第三版概念接入真实对局。飞入放慢至约620毫秒，每张卡先展示约800毫秒，再由服务端发出响应请求，开始完整10秒响应窗口。新增卡牌飞入、金属链、编号、结算前的 `Successful Chain` 和按真实结果逐项突出的倒序结算；没有加入轰炸、冻结等单卡战场动画。

用户另已确定：连锁直接分出胜负时，先播放完整连锁演出，再进入胜负页。实现保留终局空栈快照之后仍在传输的结算结果，避免提前跳页。

## 实现边界

- 使用已有 `magic_chain_updated`、`chain_request`、`chain_resolved`，没有新增协议字段、事件或依赖。
- 只有实际新增卡牌时关闭旧响应面板；重复栈帧不会重播或关闭仍有效的响应窗口。
- 新的入链等待由现有房间任务注册表安排；出牌回执立即返回，避免目标选择层遮住本人的演出。放弃响应不重复等待，过期任务不会开放旧窗口。
- 展示队列不改手牌、棋盘或牌效结果；无效标记使用服务端结果，不自行推断。需要选船、重摆或选目标时优先保证交互。
- 重连快照只恢复基线；离开页面、断线、页面隐藏和减少动效会清理过时演出。Canvas叠层不参与布局、不拦截点击。
- 额外验证了绘制耗时跨过截止时刻的慢帧；结束时仍安排一次清理帧，最后一张卡不会残留。

## 旧脚本的基线失败

额外运行现存卡牌回归脚本时，有18项通过、3项失败。将本次修改前HEAD的 `magic.py` 提取到仓外，用相同输入重新运行，得到相同三项失败，因此不把它们算作本次通过，也不修改本轮范围外的单卡规则：

1. `codex-backend-boundaries.py`：`灵气复苏只能在原船位重布`，返回“当前没有待处理的魔法卡选择”。
2. 同脚本：`双方完成重布后清掉布船义务`，返回同上。
3. `codex-contract-completeness.py`：`疗愈增加两艘产生两艘对方部署且不递归`，旧输入未指定当前规则要求的沉船，返回“请选择一艘或两艘要原地复活的沉船”。

对照命令为 `python regression.py <脚本名>` 与 `python regression.py <脚本名> --baseline`；旧夹具中展示等待显式设为0，真实0.8秒计时另由专项测试验证。
