# 连锁响应权与服务端调度修复（2026-10-24）

## 现象

AI 出牌 → 人类接一张速阶 3 连锁 → 界面停约 10 秒才结算；人类也没机会继续追加连锁。

## 根因（两处，都在服务端）

### 1. 会开出一个「谁都答不了」的连锁窗口

`domain/magic/chain.py` 的 `can_respond` 只看手牌里有没有速阶 3：

```python
def can_respond(room, player_id):
    ...
    return bool(speed3_cards(player))
```

但「手牌里有速阶 3」不等于「这张能出」——速阶 3 的实际可用性由
`domain/magic/rules.py::evaluate_cast` 判定（角色阶段、`last_attack`、王阳/我心/滥竽、
选船待办、registry 是否接入等）。

于是出现这条时间线（仓外 `probe_chain.py` 复现，人类船已满 6/6、手里只有「滥竽充数」）：

```
+0.00s chain_request to=human caster=ai-1 countdown=10 speed3=2
+0.00s chain_request to=human caster=p1    countdown=10 speed3=1   ← 又开回人类
+10.00s chain_resolved                                            ← 只能等超时
```

AI 无合法响应自动 pass 之后，窗口按「人类还有速阶 3」又开回人类；可人类那张
「滥竽充数」因满船根本用不了，双方都只能空等 10 秒。这就是「停约十秒才结算」。

### 2. `chain_response` 先关窗、后校验 → 拒绝一次就把连锁锁死

`services/magic.py::chain_response` 修复前在参数解析之后立刻：

```python
room.chain_waiting = False
room.chain_window = None
```

然后才校验手牌/速阶/`evaluate_cast`，三条拒绝分支直接 `return {"status": "error"}`。
结果是：一次非法响应（例如点了不可用的卡、或载荷不合法）就把窗口和定时器一起清掉，
连锁既不结算也不再接受合法响应——`probe_chain.py` 的 P5.5 实测为
`settled after -1.00s`（永不结算），前端表现就是「卡住」。

## 修复

1. `backend/src/battleship/domain/magic/chain.py`
   - 新增 `usable_speed3_cards(room, player_id)`：速阶 3 且 `evaluate_cast(...) is None`。
   - `can_respond` 用它判断，不再用 `speed3_cards`。
2. `backend/src/battleship/services/magic.py::_advance_chain_window`
   - `chain_request` 载荷补 `responder`（窗口归谁）与 `self_chain`（是否本人自连锁）。
     自连锁时 `caster` 就是自己，前端只看 `caster` 会把「自己在追加连锁」误判成「对方在连锁」。
   - `speed3_cards` 改发 `usable_speed3_cards`，前端不会再列出用不了的卡。
3. `backend/src/battleship/services/magic.py::chain_response`
   - 关窗只发生在「真正提交」时：`magic_blocked`、`evaluate_cast` 拒绝两处先显式关窗
     再 `_pass_after_refusal`；纯校验失败（卡数据非法、不在手牌、不是速阶 3）直接返回，
     **窗口继续属于本人**，10 秒超时仍然兜底。

保留：鉴权（`identity_ok`）、`chain_display_delay_seconds=1.2` 展示延时、
`chain_response_seconds=10`、`ai_chain_delay_seconds=0.8`、双方连续 pass 才结算、
速阶 3 的「任意阶段可出」规则均未改动。
