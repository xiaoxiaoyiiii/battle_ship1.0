# 连锁逐张结算与战斗交互

## 结算与演出

原实现先执行整条连锁，再发结果供前端演出，导致卡面挡住已经变化的棋盘，AI也可能抢先行动。现在逐张处理：双方展示卡面、卡面离场、客户端回执、服务端执行该张效果并同步棋盘与手牌。首次结算前保留 Successful Chain，顺序仍为后发动先结算。

新增公开事件 `chain_resolving`，只包含公开连锁、当前序号和该项真实无效标记。`chain_animation_complete` 用于登记播放能力和回传当前演出标识；服务端验证房间、座位及当前连接，等待所有已登记的在线真人。旧标识不能释放下一张演出，断线和失回执有界退出。最终 `chain_resolved.presented=true` 只收尾，不再重复演出。

AI在整条连锁结算期间等待，连锁内部反制保持原流程。炮击也受结算门禁限制。等待离场期间若玩家主动投降等外部终局发生，停止尚未生效的牌并统一清理；连锁本身产生的胜负仍先完成该次结算演出，再进入结果页。

## 卡牌与摸牌

未能复现“普通连锁第二张必被无效”。普通三链“轰炸、百亿补贴、盗亦有道”中第二张正常生效，盗亦仅取得卡牌，不设置无效标记。发现并修复的相关问题是盗亦仅查询已结算历史，遗漏当前连锁；现在按宣告时间选择栈或历史中对手最近未被盗的牌，按连锁项记录归属，避免同名牌互相影响以及失败退款复制。

连锁响应同时更新本次的卡牌禁用原因，避免沿用入链前“对方还没打牌”的旧提示阻止合法第三链。

牌库沿用双方共享规则。`RoomSync.deck_count` 提供真实剩余数量，`card_drawn` 仅公开摸牌者、数量与入手或弃牌去向，不公开对手卡面。跨页面接收开局、回合与效果摸牌；桃园结义在确认分配后播放实际获牌者的动画。自己的牌飞向手牌区，对手只显示牌背并飞向头像。退款、盗取、弃牌回收和重连同步均不触发摸牌动画。

## 交互窗口与重开

阶段响应、目标区域、选船、护盾、候选卡、部署、弃牌和连锁响应统一放大文字与卡面，突出步骤、已选数量及确认状态，支持拖动标题。棋盘目标窗口保持非模态；手机目标窗口限制高度，允许拖动后露出棋盘。`AppOverlay.draggable` 默认关闭，其他页面维持原有行为。

AI再来一局原先在新房间到达后清空了整个游戏状态，并遗留旧摆船提交锁及首页等待标志。现在成功加入后仅清理旧局展示和交互状态，保留新房间；创建失败仍保留结算以供重试。
