## 三、行为约定（本轮确定并写进代码注释）

1. **非法目标不吞卡**：形状/连通/行列校验在 `sanitize_targets` 里就返回错误，早于扣牌与入链。
2. **多张待选牌依次进行**：一次只激活一项；确认/取消后自动提升下一项，并在响应里带
   `next_temp_data_id`/`next_temp`，前端不需要自己猜。
3. **败者食尘不负责清连锁**：`chain` 与 `magic_discard` 由 `_resolve_chain` 收尾，
   否则同一串里的下层卡既不被结算也不退牌。
4. **AI 座位不留待选**：AI 的 `request_ship_pick` 同步返回答案的效果必须在同一次调用里
   落地（仁王之盾加盾 + `temps.finish`），否则 AI 回合会停在「等人点」。
5. **神之宣告不替玩家做选择**：未显式选满两艘就拒绝并退牌。
6. **恶魔契约只按「被击杀」触发**：触发点在 `on_ship_sunk`，献祭链路不递归——卡面写明
   「每一次攻击生效后只结算一次」，与原 main 的 `sacrifice_request` 弹窗行为一致。
7. **重连只给自己看自己的待选**：`magic_temp` / `dice_discard_pending` 对对手与观战是
   `null` / `false`；`max_ships` 与 `needs_reset` 用来整盘重布。

## 六、复核轮（2026-10-24 第二批：用户定稿 + Codex 边界脚本）

### 6.1 第二批实现记录（后续漏算修正见第七节）

上一轮按原 main 判断「只按被击杀触发、献祭不递归」，本轮用户明确改成**两个方向都绑定**：

| 方向 | 触发点（唯一入口） | 对手侧动作 |
| --- | --- | --- |
| 增加 N 艘 | `services/magic.py` 的 `confirm_reinforcement_position`（增援/复活/神机重布落地） | `_start_placement(..., "contract_gain", N)` → 对手获得 N 艘部署义务（共用 `placement_request`） |
| 减少 N 艘 | `on_ship_sunk`（炮击与效果击杀的唯一漏斗） | `sacrifice_request`（`reason=demon_contract`），对手点自己的活舰献祭 |

三条硬约束落在 `domain/magic/contract.py`：`mirroring()` 让镜像自身不再触发契约；
`enabled()` 在零变化/无效化时不成立；`suppressed()` 包住整盘重布与临时增减
（灵气复苏、败者食尘、回光返照、绝处逢生、神威的临时除外与返还、滥竽充数的临时船收回）。
契约赠送的船带 `pending_placement.mirrored=True`，落地时不再反向补船，避免两人互送。

### 6.5 第二批当时的边界判断（临时增减豁免已撤销）

- **临时增减不镜像**：神威的「除外/返还」与滥竽充数的「临时船收回」按整盘临时态处理，
  不算真实增减（否则一次除外会被镜像成对手白送船，返还时又变成双方互杀）。
- **整盘重布不镜像**：灵气复苏/败者食尘/回光返照/绝处逢生期间 `suppressed()`，避免把
  中间态当成击杀。
- **镜像数量**：一次原始变化镜像 1 次；连续沉船来自多次独立击杀（每次攻击/每次效果击杀
  各一次），因此 N 艘沉没会产生 N 次献祭请求，而不是一次 N 艘——与本轮验收脚本一致，
  但「一次性 N 艘」若产品希望合并成一条请求，需要前端面板支持数量后再改。
- 真实 Socket.IO 端到端仍未在本轮跑（服务层 + 记录型 publisher）；`probe_c2.py`/`probe_sync.py`
  因 `RecordingPublisher` 增加第三列（`to`）而改了两行解包，属实现细节适配，已在此说明。
- 仓外 22 条浏览器基线门禁本机仍无基线，未跑。

### 7.2 恶魔契约定稿

用户明确“增加和减少都要绑定”，因此第六节所写临时船豁免不是当前规则。

1. 单张魔法执行期间屏蔽中间回调，成功后按各方实际净增减统一镜像；覆盖原地复活、多艘献祭、区域多杀，避免遗漏或重复。
2. 增援逐艘落地后让对方获得对应数量的部署；镜像赠船本身不再反向赠送。
3. 神威除外与返还、临时船补充与收回均按实际变化绑定。
4. 绝处逢生清空不是最终结果，真人等待唯一战舰落地后按净减少结算；AI在效果内部同步落地时直接按最终数量结算。
5. 灵气复苏、败者食尘、回光返照属于整盘替换，不将清空重摆的中间状态当作逐艘击杀。契约只要仍在场就保留，场地移除或替换由既有场地生命周期清理。
6. 镜像献祭不再次触发镜像；终局清理队列和宣言定时器。多艘义务仍逐艘确认，不隐式随机替玩家献祭。
