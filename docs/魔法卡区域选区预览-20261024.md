# 魔法卡区域选区预览（2026-10-24）

只改战斗界面「选目标」这一层的画法：规则的尺寸、左上角锚点语义、确认/取消流程、服务端目标数据全部没动。
方向按任务要求取 **A＋D**：一条完整外轮廓 + 很淡填色；五种卡各用自己的主题色。

顶部目标操作窗、聊天窗、日志、连锁、手牌、右下通知。

## 二、视觉策略

- **不再满屏提示**：没有选中格子时棋盘保持原样，可点范围只靠光标与很轻的悬停反馈表示（不再刷"+"、不再给每个格子加虚线、不可选格也不刷叉）。
- **一片一个轮廓**：把「相邻格也在范围内」的边去掉，只画暴露边；矩形得到完整外框，轰炸得到整行/整列条带，硫磺火焰六格得到真实并集轮廓（不会退化成包围矩形、暗示额外作用格）。
- **克制配色**：填色 `color-mix(主题色 10%)`，斜纹约 5%，边框 `color-mix(主题色 72%, white)`，外发光 5px/30%；`prefers-reduced-motion` 下取消发光。三套主题（航图/航海日志/夜航）都没写死颜色，只用既有主题变量与本层色相。
- **角标**：贴并集左上角内侧，偏移 4px，永远在棋盘内，边缘格不会被裁掉。

## 四、已知不足

1. **真实 Socket 确认链路本轮没跑通**：这个仓库没有夹具 HTTP 端点，人机房间要靠界面创建，脚本走到布船页后拿不到房间座位号，`test_add_specific_magic_card` 一直回「无效的房间或玩家」。
   本轮证据是"初始局面/发牌用夹具 + 真实渲染与真实鼠标点击"；出牌到服务端那一步由上一批 Codex 的 `codex-wire-ui.mjs`（区域组 7 张卡）覆盖。
   预览层本身 `pointer-events:none`，且脚本逐格核对过 36 格中心 `elementFromPoint` 仍命中格元素，所以它不可能改变出牌链路。
2. **窄屏下棋盘本身偏小**：390×740 / 844×390 时棋盘被 HUD 与手牌挤压（本次基线上就如此，`head-390-baseline.png` 与改动后一致），预览层跟着棋盘走，没有额外遮挡；要改棋盘尺寸属于布局任务，不在本次范围。
3. 棋盘里少数格子显示"⇩"占位图标，是本次基点带入的既有状态（改动前后一致），没有在本轮处理。
4. 没跑仓库里不存在的「22 项浏览器门禁」；本轮只跑了 `typecheck`、生产 `build`、`git diff --check`。
